# 自动生成关卡配置规范（Bubble 当前项目）

版本：2.1.0  
整理日期：2026-08-21  
适用工程：`E:\coco_project\bubble`  
正式关卡范围：1～1000 关  
正式生成器：`tools/generate-1000-level-configs.js`  
统一策略：`tools/campaign-level-generation-config.js`

## 1. 目标、范围与权威来源

本规范用于生成、校验和发布当前 Bubble 项目的静态关卡配置。它覆盖：

- 正式 1～1000 关的普通限球关、90 秒限时关、单目标被困精灵救援关和多目标精灵救援关。
- 当前引擎能够解析的全部棋盘特殊球、危险球、附着物和结构机关。
- 已进入正式 1000 关排期的全部特殊实体、附着物、环境机关和初始道具库存。
- 本地完整 JSON、远程 `compact-schema-v2` 关卡包、manifest、编辑器和运行时之间的同步要求。

本文只规范“由关卡配置驱动”的玩法。玩家养成、商城、活动奖励、精灵等级等不属于关卡生成范围。

发生冲突时，按以下顺序确定当前合同：

1. `assets/scripts/config/LevelConfigLoader.js`、`LevelBoardSupportValidator.js`、`BoardOcclusionConfig.js` 的严格校验。
2. `gameplay-src/` 中的真实结算和状态机。
3. `tools/campaign-level-generation-config.js` 与 `tools/campaign-special-mechanism-schedule.js` 的正式战役排期。
4. `LEVEL_CONFIG_TABLE_1_1000.csv` 的逐关球量、全部特殊玩法、模式、目标和发射数；`docs/1000关逐关特殊玩法配置.md` 是同步的人读版本。
5. `tools/generate-1000-level-configs.js` 的布局、投放、打包实现。
6. 本文和其他设计文档。

`E:\kxppm\docs\自动生成关卡配置规范.md` 只作为文档结构和验收闭环参考。当前项目不得导入参考工程的字符语义、`appendItems`、发射数、计时模式、分数、机关参数或胜负规则。1～300 关仅允许从 `E:\kxppm\decrypted_config\all_levels.json` 提取占位/空位轮廓。

## 3. 完整关卡数据合同

### 3.1 外层结构

正式完整 JSON 使用以下外层字段：

```json
{
  "schemaVersion": 1,
  "gameMode": "glass_marble_bubble",
  "coordinateSystem": "odd-r-hex",
  "layoutNotes": {},
  "sharedDefaults": {
    "collectMode": "any_with_same_color_bonus",
    "loseConditions": [],
    "fallingRules": {}
  },
  "level": {},
  "difficultyScaleMax": 100
}
```

硬约束：

- `schemaVersion` 必须为 `1`。
- `coordinateSystem` 必须为 `odd-r-hex`。
- 正式文件名为 `level_###.json`，`level.levelId` 必须与文件名一致。
- `level.code` 必须以 `L###_` 开头。
- `layoutNotes`、`teaches`、`designNotes` 属于完整配置的设计说明；紧凑包可以删除，但不得替代真实玩法字段。
- `sharedDefaults` 在远程包头中只保存一份，所有包内关卡必须完全一致。

### 3.2 `level` 必填字段

普通限球关至少显式包含：

```json
{
  "levelId": 1,
  "code": "L001_EXAMPLE",
  "difficulty": "normal",
  "teaches": [],
  "colorCount": 3,
  "colors": ["B", "R", "G"],
  "shotLimit": 20,
  "targetScore": 10000,
  "starThresholds": {
    "star1": 5000,
    "star2": 7000,
    "star3": 9000
  },
  "dropInterval": 8,
  "jarCount": 5,
  "jarColors": ["R", "G", "B", "Y", "P"],
  "spawnWeights": {"B": 1, "R": 1, "G": 1},
  "openingShotBalls": ["B", "R", "G"],
  "jarRules": {
    "rimBounce": 0.68,
    "collectZoneScale": 1.1,
    "sameColorBonus": 1.5
  },
  "winConditions": [{"type": "collect_color", "color": "B", "value": 20}],
  "bonusObjectives": [{"type": "clear_with_shots_remaining", "value": 3}],
  "clearRewardItems": [{"id": "coin", "count": 50}],
  "layout": [],
  "specialEntities": [],
  "levelType": "normal",
  "playMode": "shot_limited",
  "initialDropSpaceRows": 8,
  "adPowerupRules": {
    "allowed": ["three_line_elimination", "plus_three_balls"]
  },
  "boardOcclusionPlan": {
    "generatorVersion": 1,
    "mode": "none",
    "variants": []
  }
}
```

其他约束：

- `colors` 只能使用 `R/G/B/Y/P/O/K/W`，无重复，单关最多 5 色。
- `colorCount` 必须等于 `colors.length`。
- `spawnWeights` 必须只包含当前 `colors`，每个权重都大于 0。
- `jarCount` 固定为 5；`jarColors` 固定包含且只包含 `R/G/B/Y/P`。
- `shotLimit` 为正整数且不大于 54；限时关禁止配置该字段。
- `targetScore` 为正整数；`star1 < star2 < star3 <= targetScore`。
- `dropInterval` 为正整数；单目标旋转救援关禁止配置。
- `initialDropSpaceRows >= 8`；单目标旋转救援关禁止配置。
- `initialShotBalls` 只能写 1～2 个当前关颜色。
- `openingShotBalls` 只能写 3～6 个当前关颜色，只用于普通棋盘的 `shot_limited`，并且与 `initialShotBalls` 互斥。
- `clearRewardItems` 必须非空且包含金币；金币 50～300，体力 1～3。
- `adPowerupRules.allowed` 只允许 `three_line_elimination`、`plus_three_balls`；限时关禁止 `plus_three_balls`，单目标旋转救援关必须为空数组。

### 3.3 目标类型

`winConditions` 支持：

- `clear_all`
- `collect_any`
- `collect_color`
- `collect_ice_snowball`

`bonusObjectives` 额外支持：

- `collect_same_color_bonus_hits`
- `clear_with_shots_remaining`
- `single_turn_drop_count`

生成规则：

- `clear_all.value` 必须为 1。
- `collect_color.color` 必须同时存在于 `colors` 和 `jarColors`。
- 有分裂球时，全关分裂球必须使用同一个 `splitColor`；`winConditions` 必须恰好有一个相同颜色的 `collect_color`。
- `collect_ice_snowball.value` 不得超过关内冰球数量；正式表中的第二目标必须等于冰球数量。
- 当前通关最终仍以清屏和一星分数线为准；`bonusObjectives` 决定额外奖励，不得被生成器误当成唯一胜利条件。

## 4. 棋盘几何与布局生成

### 4.1 行宽和字符

- 行、列从 0 开始。
- 偶数行（0、2、4……）固定 11 列。
- 奇数行（1、3、5……）固定 10 列。
- 普通球直接使用颜色字符 `R/G/B/Y/P/O/K/W`。
- `.` 表示空位，也表示 `specialEntities`、救援中心或虫洞端点预留格。
- 正式生成器必须直接输出完整 11/10 行宽。加载器虽然能补齐短行，但生成器不得依赖该规范化行为。
- 棋盘至少 8 行，至少 8 个实际占用行；中间不得用无意义空行规避难度或支撑校验。

### 4.2 odd-r 六边形邻接

同行邻居恒为 `(r,c-1)`、`(r,c+1)`。

偶数行其余邻居：

```text
(r-1,c-1) (r-1,c) (r+1,c-1) (r+1,c)
```

奇数行其余邻居：

```text
(r-1,c) (r-1,c+1) (r+1,c) (r+1,c+1)
```

不得混用参考项目的另一套奇偶偏移定义。所有支撑、漩涡轨道、附件邻接、蜘蛛宿主和救援目标校验都必须复用当前项目坐标函数。

### 4.3 普通棋盘硬约束

1. 顶行至少有一个真实支撑实体；虫洞端点不计入顶行支撑。
2. 从顶行支撑做 BFS，初始棋盘所有实际占用球必须可达。
3. 全图按 odd-r 六方向邻接统计的普通球同色连通块不得超过 8 个；顶行横向连续同色普通球不得超过 3 个，空位和特殊实体会打断连续段。
4. `normalBallCount / (boardCapacity - specialEntitySlots - trappedSpriteAnchorSlots) >= 70%`。
5. 正式目标占位率为：1～300 关 70%，301～500 关 72%，501～700 关 74%，701～1000 关 76%。
6. 特殊实体先占位，普通颜色后填充；不得先填色后覆盖，以免球数、目标量和支撑统计失真。
7. 每个 `specialEntities` 项必须有唯一 `id`、唯一 `(row,col)`，并且只能放在布局字符 `.` 上。
8. 同类特殊位置不得与上一关完全重复；同类位置签名在连续 5 关内最多出现 2 次。

单目标旋转救援关不使用顶行支撑和矩形占位率，执行第 8.2 节的中心锚点合同。

## 5. 正式 1000 关生成策略

### 5.1 输入和确定性

正式生成输入由以下内容共同组成：

- `LEVEL_CONFIG_TABLE_1_1000.csv`：颜色球数、行数、全部特殊实体、三类附着物、蜘蛛、彩云、救援模式、初始棱镜库存、限时球、遮挡、目标、发射数和通关率设计值。
- `docs/1000关逐关特殊玩法配置.md`：与 CSV 同步生成的 1～1000 关逐关人读配置；必须先运行 `node tools/rebuild-relaxed-campaign-level-configs.js --table-only` 生成并审查，再执行全量关卡生成。
- `tools/campaign-special-mechanism-schedule.js`：新增机制首次关卡、150 关复现间隔和单关数量的统一排期。
- `campaign-level-generation-config.js`：颜色解锁、模式、漩涡/藤蔓/虫洞、救援、遮挡、冰占比、分数和占位率。
- 1～300 关的 KXPPM 占位轮廓；301～1000 关的项目自有图案规则。
- 首 100 关和 101～300 关的逐关发射数校准表。

相同代码、相同 CSV 和相同参考轮廓必须生成字节级一致的完整关卡和紧凑包。当前生成链不接受“缺参考文件时改用随机布局”“没有合法机关位置时减少机关数量”或“校验失败后保留旧关卡”等兜底。

### 5.2 轮廓来源

- 1～200 关投影 KXPPM 同编号关的占位轮廓。
- 201～300 关投影 KXPPM 101～200 关的水平镜像轮廓。
- 101～300 中排定的救援关改用当前项目中心救援几何，不使用参考轮廓。
- 301～1000 使用 `arrow/heart/diamond/spiral/gate/flame/flower/keyhole/crown/wave` 项目图案。
- 参考字符只区分“占用/空位”，不得转换成当前颜色或特殊球。

### 5.3 颜色进度

| 关卡 | 单关活动色数 | 新解锁颜色 |
|---|---:|---|
| 1 | 2 | `B/R` |
| 2～8 | 3 | `G` 从第 2 关进入 |
| 9～74 | 4 | `Y` 9、`P` 21、`O` 41、`K` 61 |
| 75～1000 | 5 | `W` 81 |

颜色池解锁后按每 5 关轮换活动色。收集目标只能从罐子支持的 `R/G/B/Y/P` 中选择；不能因为当前活动色包含 `O/K/W` 就生成无法进入目标罐的收集条件。

普通关和限时关必须按 CSV 的逐色数量生成聚类候选，不能改变任一颜色的球数：

- 全图使用 odd-r 六方向 BFS 统计，任何同色连通块不得超过 8 球。
- 可形成三消的成组球覆盖率不得低于当前聚类策略计算的门槛；孤立球比例通常不得超过 10%，只有占位轮廓本身存在几何孤立槽时才能按实际孤立槽数量计算允许值。
- 收集目标色必须至少存在一个 3 球连通块，且不得产生超出几何孤立槽数量的目标色单球。
- 顶行横向连续同色仍不得超过 3 球；该规则不能替代全图六方向连通块校验。
- 候选出现超过 8 球的同色块时，只允许交换两个不同颜色普通球的位置进行确定性修复；交换必须保持逐色数量、占位轮廓和特殊球坐标不变，修复后重新执行成组率、孤立率、目标色、顶行、支撑和连锁风险全部校验。无法得到合法候选时整关生成失败。

被困精灵救援关使用独立的严格配色搜索，在每次赋色时直接限制同色连通块不超过 8，并额外执行第 8.2 节的中心六邻圈规则。

### 5.4 正式模式排期

- 每个 10 的倍数关：`special_floating_island / timed_infinite_shots`，固定 90 秒，`requiredStarCount = 1`。
- 每个 100 关章节的第 25、42、63、86、99 关：`trapped_sprite_rescue / shot_limited`。
- 救援排期与限时排期重叠时必须直接报错；当前排期已保证不重叠。
- 其他关卡：`normal / shot_limited`。

### 5.5 冰球曲线

| 关卡 | 冰球占棋盘容量比例 |
|---|---:|
| 1～15 | 0 |
| 16～30 | 5% |
| 31～60 | 7% |
| 61～100 | 9% |
| 101～300 | 10% |
| 301～500 | 12% |
| 501～700 | 14% |
| 701～850 | 16% |
| 851～1000 | 18% |

非零阶段数量为 `max(3, round(boardCapacity * ratio))`。救援关同样使用该曲线，但只能占用救援六边形中的合法普通槽位。

### 5.6 漩涡、藤蔓和虫洞进度

- 漩涡第 21 关首次出现。
- 藤蔓魔灵第 31 关首次出现。
- 虫洞第 53 关首次出现。
- 81 关起，每个十关周期组合单玩法、两两组合、三玩法同关和第十关考核。
- 后期单关上限为 3 个漩涡、3 个藤蔓魔灵、3 对虫洞。
- 救援关可保留漩涡和藤蔓，但虫洞数量必须归零。

生成位置时必须先预留每个漩涡完整六格轨道，再预留每对虫洞的两个端点和整段内部通道，最后才投放其他特殊实体和普通球。没有合法几何时整关生成失败，不能自动降数量。

### 5.7 目标分和星级线

正式目标分按实际生成结果计算：

```text
rawTarget = normalBallCount * 55
          + iceCount * 120
          + baseSpecialCount * 150
          + primaryObjectiveValue * 45
          + secondaryObjectiveValue * 80
          + swirlCount * 240
          + vineSpiritCount * 280
          + wormholePairCount * 420
          + actionBudget * 90
          + efficiencyReserve * 220

targetScore = ceil(rawTarget / 100) * 100
```

限球关 `actionBudget = shotLimit`，`efficiencyReserve = max(3, round(shotLimit * 0.18))`。限时关以 `round(timeLimitSeconds / 3)` 估算行动量，效率储备比例为 14%。

星级比例：

| 节奏 | 一星 | 二星 | 三星 |
|---|---:|---:|---:|
| introduce | 48% | 68% | 86% |
| practice | 50% | 70% | 88% |
| combine | 52% | 72% | 90% |
| twist | 54% | 74% | 92% |
| exam | 56% | 76% | 94% |
| rescue | 50% | 70% | 88% |

少量已实测高压关可由统一策略表显式覆盖一星比例或发射数；禁止在生成器内部散落无来源的关卡 ID 特判。

### 5.8 发射数

- 1～100 和 101～300 使用当前运行时模拟得到的逐关校准表；表长度、缺项和非正整数直接报错。
- 301～1000 使用当前项目生成/模拟策略，不读取参考工程发射数。
- 单目标救援关按实际普通球、行数、冰球、基础特殊球、漩涡和藤蔓数量计算，最终限制在 28～46 发，并应用统一高压关覆盖表。
- 黑洞、地雷、繁殖、花苞、透明球、精灵茧、风眼等机制未来进入正式池时，必须先扩展模拟器；禁止只在普通球公式上追加拍脑袋常数。

## 6. 全部特殊球合同

### 6.1 通用配置格式

除彩虹棱镜球外，棋盘特殊球都写在 `level.specialEntities`：

```json
{
  "id": "unique_id",
  "entityCategory": "reactive_ball",
  "entityType": "swirl",
  "row": 4,
  "col": 5
}
```

共同要求：

- `id` 非空且全关唯一。
- `(row,col)` 为合法整数坐标且全关唯一。
- `layout[row][col]` 必须为 `.`。
- 不相关的类型专属字段不得用默认值冒充合法配置。
- 进入正式远程包前必须通过 `LevelPackCompactCodec.compactPack()` / `expandPack()` 无损往返。

### 6.2 石球 `obstacle_ball/stone`【正式生成已启用】

- 不参与普通颜色匹配，作为真实棋盘占位和支撑结构。
- 可由爆破、燃烧瓶、破障锤、精灵技能等明确支持的范围入口清除。
- 自动投放必须避免把唯一通路完全封死；发射模拟必须覆盖石球拆除或支撑绕行。

### 6.3 冰球 `obstacle_ball/ice`【正式生成已启用】

```json
{
  "entityCategory": "obstacle_ball",
  "entityType": "ice",
  "innerColor": "R"
}
```

- `innerColor` 必须是合法颜色；正式生成时必须属于当前 `level.colors`。
- 相邻普通匹配消除会融化冰层并在原格恢复 `innerColor` 普通球。
- 爆破、除雪剂和明确支持的精灵技能按各自入口融冰/收集雪块。
- `collect_ice_snowball` 数量不得超过实际冰球数。

### 6.4 彩虹球 `skill_ball/rainbow`【正式生成已启用】

- 棋盘上的彩虹球是可收集技能球，不作为普通颜色球匹配。
- 收集后增加本局彩虹球库存；使用时从当前 `level.colors` 中选择一种颜色，把当前发射球转换为该颜色。
- 自动生成必须验证收集路径，不能把技能球放在永远无法消除或掉落的位置。

### 6.5 爆破球 `skill_ball/blast`【正式生成已启用】

- 棋盘实体被收集后增加本局爆破球库存。
- 发射爆破球以真实落点或碰撞点为中心，处理中心格和六个邻格。
- 冰球只融冰，未解锁锁球不被移除；气泡护盾第一次只掉盾；黑洞走专用卸载；藤蔓魔灵每次结算最多受 1 点伤害。
- 清除结果继续触发燃烧瓶、分裂球、钥匙、支撑和掉落链。

### 6.6 晶光炮 `skill_ball/crystal_gun`【正式生成已启用】

- 棋盘实体被收集后增加晶光炮库存。
- 发射后从首次命中点沿实际最终入射方向继续；反弹射击使用反弹后的最后一段方向。
- 最多扫描后续 5 个逻辑行；射线与球圆相交即命中，同一行允许多球。
- 空格不阻断；到达顶部或射线真正离开左右边界才停止。
- 弹体必须飞到最远实际消除目标的射线出射点后，才统一执行清除并消失。
- 进入正式生成池前必须把库存收益、直线多球收益和反弹路线纳入通关模拟。

### 6.7 燃烧瓶 `reactive_ball/molotov`【正式生成已启用】

```json
{
  "entityCategory": "reactive_ball",
  "entityType": "molotov",
  "blastRadius": 2
}
```

- `blastRadius` 必须且只能为 2。
- 本体或相邻格被实际清除时触发；每个燃烧瓶每次结算最多触发一次。
- 清除两圈六边形半径内的合法目标，支持燃烧瓶连锁。
- 未解锁锁球不可清除；护盾、黑洞、藤蔓魔灵按各自专用入口处理。

### 6.8 分裂球 `reactive_ball/splitter`【正式生成已启用】

```json
{
  "entityCategory": "reactive_ball",
  "entityType": "splitter",
  "splitColor": "B"
}
```

- 不参与普通匹配，禁止放在第 0 行。
- 相邻格被实际清除时触发；每个分裂球每次结算最多触发一次。
- 优先在相邻空位生成一颗 `splitColor` 普通球；没有相邻空位时寻找最近的上方空位；仍无合法位则不生成。
- 同一关全部分裂球必须同色，并与唯一 `collect_color` 目标一致。
- 目标供给按每个分裂球最多贡献 5 颗的当前表规则计算，不能把理论无限触发计入目标。

### 6.9 漩涡球 `reactive_ball/swirl`【正式生成已启用】

- 中心必须拥有完整六邻坐标；六格轨道不能含其他特殊实体，多个轨道不能重叠。
- 正式生成时六格初始轨道必须全部是普通颜色球。
- 每次发射的消除表现完成后，所有漩涡按稳定顺序把六格顺时针旋转 60°，时长 0.4 秒。
- 空位和普通球状态随轨道移动；旋转本身不触发颜色匹配。
- 动画完成后立即统一重算支撑并登记掉落。
- 漩涡中心或轨道被蜘蛛锁定时不得启动旋转；正式组合前必须有专项验证。

### 6.10 藤蔓魔灵 `reactive_ball/vine_spirit`【正式生成已启用】

- 初始固定 3 点生命。
- 直接命中、爆炸覆盖魔灵本体或六邻格发生实际消除时造成 1 点伤害；一次发射结算最多伤害同一魔灵一次。
- 每 3 次真实发射，存活魔灵按距离、行、列和 ID 稳定选择最近的未缠绕普通球；先预告 0.65 秒，再写入藤蔓归属。
- 缠绕球不能参与匹配，但仍参与支撑。只有六邻格发生实际消除才解藤蔓；只覆盖缠绕球本体的爆炸不解藤蔓。
- 魔灵死亡或无支撑掉落时，其全部活动/预告藤蔓立即枯萎。

### 6.11 虫洞 `reactive_ball/wormhole`【正式生成已启用】

```json
{
  "entityCategory": "reactive_ball",
  "entityType": "wormhole",
  "moveDirection": "right"
}
```

- 每个虫洞行必须恰好两个端点，方向同为 `left` 或同为 `right`。
- 加载器最低要求端点间至少一个内部槽；正式生成器要求列差至少 3，即至少两个内部槽。
- 不同虫洞对使用不同的行；端点及整段内部通道不能与漩涡轨道或其他预留结构冲突。
- 端点保持 `.`，独立于 `BubbleGrid.cells`，不参与匹配、支撑、危险线、清屏或顶部崩塌占位。
- 每次发射结算后、漩涡之后，严格内部区间按箭头循环移动一格；普通球、特殊球、附件、藤蔓归属和空位一起移动。
- 位移不触发颜色匹配；0.35 秒动画完成后统一重算支撑。
- 发射球直接撞到端点会被吸收、不落位，但仍消耗发射并继续后续回合阶段。

### 6.12 繁殖球 `reactive_ball/breeder`【正式生成已启用】

- 初始必须至少有一个合法六邻空位。
- 每次发射的漩涡、虫洞、藤蔓和地雷阶段结束且关卡未失败后，存活繁殖球按 ID 顺序处理。
- 若本次实际消除格与该繁殖球相邻，本回合跳过繁殖。
- 否则从实时六邻空位随机选一格，再从棋盘当前仍存在的普通颜色中随机生成一球；六邻已满时不生成。
- 新球以贝塞尔出生动画飞向权威目标格；结束后再参与普通支撑。
- 正式生成必须使用多回合增长模拟，不能只验证初始连通性。

### 6.13 花苞球 `reactive_ball/bud`【正式生成已启用】

- 普通匹配实际清除邻接格时触发，播放 `bud_1`～`bud_8` 后在原格孵化普通球。
- 普通色发射球决定孵化色；特殊发射球从当前棋盘仍存在的普通颜色集合中随机选色。
- 孵化后把实时六邻普通球染成同色；附件保留，染色不立即触发二次匹配。
- 所有花苞孵化结束后统一重算支撑。
- 爆破、燃烧瓶等范围清除直接移除花苞本体，不孵化。

### 6.14 精灵茧 `reactive_ball/spirit_cocoon`【正式生成已启用】

- 普通消除或悬空掉落发生在茧的邻格时开启；开启动画完成固定加 1000 分。
- 本地首次必出贪吃精灵；后续迷雾/贪吃/彩虹概率固定为 20%/40%/40%。
- 迷雾精灵逆时针经过当前六邻普通球并附加沙尘遮挡；遮挡随球移除，并在第 5 次后续发射统一消失。
- 贪吃和彩虹精灵沿同行逐球移动，每格 0.35 秒；前者逐球移除并加连击分，后者逐球按当前棋盘颜色序列染色。
- 整个精灵效果完成后只做一次支撑扫描。自动生成必须为三种结果分别模拟，不能只按平均收益估算。

### 6.15 透明球 `reactive_ball/transparent_ball`【正式生成已启用】

- 发射轨迹穿过透明球，以后方实体球作为真实物理终点。
- 发射球越过记录命中点的同一帧移除透明球；若透明球与后方实体相邻，最终强制吸附到透明球原槽位。
- 每个透明球固定加 1000 分；即使没有三连也执行支撑扫描并视为有效消除。
- 生成器必须用真实轨迹证明透明球后方存在稳定合法碰撞终点，禁止把它随机放入死角。
- 当前禁止用于单目标旋转救援关。

### 6.16 黑洞 `hazard_ball/black_hole`【正式生成已启用】

```json
{
  "entityCategory": "hazard_ball",
  "entityType": "black_hole",
  "capacity": 3
}
```

- `capacity` 必须显式为 3。
- 直接命中会吞噬发射球，不落位、不匹配，但正常消耗发射并推进回合。
- 第 3 次吞噬后黑洞移除，并立即重算支撑和掉落。
- 爆破、燃烧瓶、消三行、闪电链和龙卷风命中时走专用“卸载黑洞”入口，直接清除，不扣吞噬次数。
- 失去支撑时原地缩小消失，不进入物理掉落和罐子计分。
- 正式生成必须把 3 次强制吞噬计入可通关模拟和发射预算。

### 6.17 地雷 `hazard_ball/mine`【正式生成已启用】

```json
{
  "entityCategory": "hazard_ball",
  "entityType": "mine",
  "initialLife": 6
}
```

- `initialLife` 必须为正整数。加载器允许省略并规范化为 6，但自动生成必须显式写出，避免隐藏参数。
- 每次真实发射的拓扑变化全部完成后检查六个有效邻位；没有全部占满时立即启动，并在本次发射减 1。
- 倒计时启动后即使重新封闭也不会暂停。
- 生命归零立即移除地雷、播放爆炸、棋盘灰显并进入不可复活的 `lost_hazard`。
- 在归零前通过普通清除、范围清除或悬空掉落移除后，不再参与倒计时。
- 正式生成必须模拟“首次暴露时刻—剩余生命—最短清除路径”，不能仅检查初始状态。

### 6.18 风眼入口/出口【正式生成已启用】

配置类型：

```text
reactive_ball/wind_tunnel_entrance
reactive_ball/wind_tunnel_exit
```

- 一关必须恰好一个入口、至少两个出口。
- 入口独立于真实棋盘占位；出口进入棋盘支撑图，但标记为可穿越，不作为普通碰撞终点。
- 系统每 3 秒从当前出口之外随机激活一个出口。
- 发射球在入口缩小，从抵达入口时的激活出口放大吐出，并保持进入入口时的最终方向继续飞行。
- 如果续飞最终停在出口格，该出口被堵塞并移除；活动出口被移除后必须立即选出唯一新活动出口。
- 出口失去支撑时直接消失，不进入物理掉落。最后一个出口消失后入口依次播放 `air_intake_01`～`05` 并退场。
- 自动生成必须保留入口可命中通道，并分别验证每个出口的继续飞行、堵塞和支撑路径。

### 6.19 锁球和钥匙【正式生成已启用】

```json
[
  {
    "id": "lock_01",
    "entityCategory": "locked_ball",
    "entityType": "locked",
    "lockedColor": "R",
    "row": 6,
    "col": 0
  },
  {
    "id": "key_01",
    "entityCategory": "key_ball",
    "entityType": "key",
    "row": 6,
    "col": 5
  }
]
```

当前权威合同：

- 每个锁链行恰好一把钥匙、至少一个锁球。
- 该行 `layout` 必须全为 `.`，且不得包含任何其他特殊实体。
- `lockedColor` 必须属于 `level.colors`。
- 最下方仍未解锁的锁链行是当前边界；其上所有球置灰并禁止普通/范围清除。
- 钥匙自身或邻格被实际清除时收集钥匙，一次把同行全部锁球替换为各自 `lockedColor` 普通球，再重算支撑。
- 不再使用 `lockGroup/unlockGroup`，也不再按一把钥匙对应一个锁球生成。

### 6.20 彩虹棱镜球 `rainbow_prism_ball`【正式初始库存已启用，不能写入关卡实体】

- 通过 `level.initialPowerups.rainbow_prism_ball` 配置非负整数初始库存；`LevelConfigLoader` 不允许把它写成 `specialEntities`。
- 真实首次接触普通球时取该球颜色；首次接触非普通对象时，从当前可视棋盘仍存在的普通颜色中随机选色。
- 只扫描 HUD 下边界与炮台上边界之间的实时可视棋盘，不清除屏幕外隐藏行。
- 同色球从最底可视行到最顶可视行逐行消除，每行内同时碎裂；全部结束后只做一次支撑扫描。

## 7. 附着物和独立结构机关

### 7.1 单元附着物 `level.cellAttachments`

共同合同：

- 只能附着在 `layout` 中的普通颜色球上，不能附着特殊实体或空位。
- `id` 和坐标均唯一；同一格不能叠加两种附件。
- 漩涡和虫洞搬移普通球时，附件必须随球移动。

毒液：

```json
{"id":"poison_01","type":"poison","row":6,"col":3,"particleCount":3}
```

- `particleCount` 必须且只能为 3。
- 只有普通匹配清除该附着球时生成三滴不同初速的毒液；悬空掉落不生成。
- 毒液进入物理掉落，命中固定精灵后使对应精灵离场。
- 独立测试关为 `assets/map/config/levels/level_poison_attachment_test.json`：最低占用行中央六颗红球配置毒液附着，底部保留完整射击行，首发红球普通匹配后一次释放十八滴毒液。

冰凌：

```json
{"id":"ice_crystal_01","type":"ice_crystal","row":6,"col":3}
```

- 普通匹配清除时，每个附着球生成一根完整冰凌柱；悬空掉落不生成。
- 冰凌柱直落，命中固定精灵后使其离场。

气泡护盾：

```json
{"id":"shield_01","type":"bubble_shield","row":6,"col":3}
```

- 被护盾覆盖的普通球不参与普通同色搜索。
- 相邻普通匹配清除先拆盾，保留底层球。
- 爆破、燃烧瓶、晶光炮、彩虹棱镜、精灵技能和消三行第一次命中只移除护盾；下一次合法命中才能清除底层球。

三类附件当前均未进入正式 1000 关生成池。正式启用前必须在紧凑包往返、编辑器导入导出、特殊球位移和对应掉落模拟中逐项验证。

### 7.2 蜘蛛锁行 `level.spiderRows`

```json
{
  "id": "spider_01",
  "lockRowId": "spider_row_06",
  "row": 6,
  "col": 3
}
```

- 蜘蛛锚点必须是普通球，不得与特殊实体或附件重叠。
- 同一行所有蜘蛛必须共用一个 `lockRowId`；一个 `lockRowId` 不得跨行。
- 活动蛛网把整行普通球标记为不可匹配，空位运行时补 `spider_cocoon`。
- 范围特殊效果只能处理当前最底活动蜘蛛层及其下方目标，不能越过该层攻击上方保护区。
- 清除非最后一只蜘蛛的宿主球时，在原位补茧并保持整行锁定。
- 清除最后一只蜘蛛时，整行解锁并一次清除全部茧。

### 7.3 彩云 `level.colorClouds`

```json
{
  "visible": true,
  "position": {"x": -210, "y": -190},
  "hitDispearTime": 2,
  "startTime": 0,
  "speed": 60,
  "color": "R"
}
```

- 每项必须且只能包含上列六个字段。
- `position.x/y` 为有限世界坐标；`hitDispearTime` 为正整数；`startTime >= 0`；`speed` 为非零有限数。
- `color` 为当前 `level.colors` 之一或 `RAINBOW`。
- 到达 `startTime` 后按有符号速度在左右边界间连续反射移动。
- 飞行球每次重新进入云区计一次命中并立即变色；普通云改为固定色，彩虹云从当前关颜色随机取色。
- 达到 `hitDispearTime` 后冻结在命中位置，原地淡出并移除。

### 7.4 加时球 `level.timeBonusBalls`

```json
{"row":5,"col":3,"bonusSeconds":5}
```

- 仅限 `timed_infinite_shots`。
- 每关 2～5 个，坐标唯一，只能落在现有普通球上。
- `bonusSeconds` 固定为 5。
- 正式排期数量在 2～5 之间随每个十关限时关循环。

### 7.5 动态棋盘遮挡 `level.boardOcclusionPlan`

- 1～30 关和单目标救援关必须使用 `mode: "none"`、空 `variants`。
- 31 关起正式使用 `per_attempt_no_repeat`；普通关尝试间在 4 个预生成变体中循环且连续不重复。
- 80 关起每个变体从 1 个遮挡区提升为 2 个。
- 每区 3～7 个互相连通的普通占位格，不能覆盖特殊实体；同一变体内区域不能重叠。
- 视觉只允许 `cloud` 或 `leaves`。
- 限球关使用 `item_or_shots`，正式生成 4～6 发后自动清除。
- 限时关使用 `item_or_seconds`，正式生成 12～18 秒后自动清除。
- 除雪剂可以主动清除全部活动遮挡。

## 8. 特殊关卡类型

### 8.1 限时特殊浮岛

```text
levelType = special_floating_island
playMode = timed_infinite_shots
timeLimitSeconds = 90
requiredStarCount = 1
```

- 禁止 `shotLimit`、`openingShotBalls` 和 `plus_three_balls`。
- 必须配置 2～5 个加时球，每个固定 +5 秒。
- 动态遮挡清除规则必须按秒，不得按发射数。
- 限时期间打开特殊说明弹窗会暂停计时；生成模拟不得把说明停表计入玩家可操作时间。

### 8.2 单目标被困精灵旋转救援

```text
levelType = trapped_sprite_rescue
playMode = shot_limited
```

正式几何合同：

- 中心 `anchorCell` 固定为第 6 行中央格，保持 `.`。
- 中心外严格生成六角距离 1～5 的完整正六边形，共 90 个占用格；顶行全空。
- 支撑只从中心六邻格开始，第 0 行不提供支撑。
- 同色连通块最多 8 球；中心六邻圈顺时针连续同色最多 2 球。
- `spiritId` 严格从 `milu/lumi/noya/flora/loco/kelu/yumi` 循环。
- `worldCenter`、`renderScale` 和 9 个旋转参数必须完整显式生成。
- 只允许彩虹球、爆破球、石球、冰球、漩涡和藤蔓魔灵。
- 燃烧瓶、分裂球、虫洞、锁球、钥匙、计时、动态遮挡、普通棋盘下压、危险线和额外固定锚点全部禁止。
- 漩涡与藤蔓阶段必须等待整盘受力旋转停止，禁止拓扑动画并行。

### 8.3 多目标普通棋盘救援

```json
{
  "levelType": "multi_trapped_spirit_rescue",
  "playMode": "shot_limited",
  "multiTrappedSpiritRescue": {
    "targets": [
      {"spiritId":"milu","row":3,"col":4},
      {"spiritId":"lumi","row":5,"col":5}
    ]
  }
}
```

- 配置 2～7 个不重复精灵和不重复坐标。
- 目标格必须非顶行、保持 `.`、不与特殊实体重叠，并至少邻接一个可消除普通球。
- 使用普通棋盘支撑、视口推进、危险线和非旋转坐标。
- 普通三连按被清除球邻格救援；未三连按真实落点邻格救援；每个目标固定 1000 分。
- `winConditions` 必须恰好为 `[{"type":"clear_all","value":1}]`，一星线不得超过目标数乘 1000 的保证救援分。
- 正式排期为 401、551、701、851 关，每关 2 个目标；这些关卡禁用动态遮挡，并移除依赖 `collect_color` 胜利目标的分裂球等不兼容配置。

## 9. 多机制结算顺序和组合原则

同关存在多个机制时，生成模拟器必须按当前权威顺序推进状态，不能把效果当作可交换的静态加减法：

1. 发射碰撞、落位或虫洞/风眼吸收路径确定。
2. 普通匹配、爆破/晶光炮/彩虹棱镜等本次清除，以及护盾过滤。
3. 钥匙、燃烧瓶、分裂球、附件、花苞、精灵茧等由本次实际清除触发的阶段完成。
4. 消除表现完成后执行漩涡旋转并重算支撑。
5. 执行全部虫洞通道位移并统一重算支撑；位移不主动匹配。
6. 每第 3 次真实发射执行藤蔓预告和缠绕。
7. 地雷检查暴露并递减生命；归零立即失败，后续阶段不得继续。
8. 存活繁殖球增长。
9. 普通棋盘再处理视口/下压和下一次输入恢复。

组合原则：

- 任一机制没有组合专项测试时，不得进入正式随机组合池。
- 蜘蛛锁层、锁链保护层、护盾、黑洞都必须先过滤范围目标，再执行统一清除。
- 漩涡和虫洞搬移时必须保持颜色、特殊实体字段、附件、藤蔓归属、地雷生命和黑洞剩余容量。
- 一次结算中的支撑扫描次数和时机属于玩法合同；不得为了简化模拟提前掉落或重复掉落。
- 单目标救援、计时、虫洞和动态遮挡的现有互斥必须由策略层直接拒绝，不在运行时降级。

## 10. 新机制进入正式自动生成池的门槛

每种新增或从测试池转正式池的机制，必须一次完成以下链路：

1. `LevelConfigLoader`：类别、类型、必填字段、坐标、互斥和非法组合 Fail-Fast。
2. `LevelPackCompactCodec`：完整配置到 `compact-schema-v2` 无损往返；新增字段即使暂时直通，也要有非法结构测试。
3. `validate-level-content`：正式离线校验器同步白名单和类型专属规则。
4. 关卡编辑器：导入、导出、保存和重新加载不丢字段。
5. 运行时：权威状态、结算顺序、支撑、掉落、失败和重试完整。
6. 表现和资源：预加载、Sprite/动画、说明图、释放与重新进入。
7. 独立测试关：只测试该机制及必要交互，不重生成 1000 关来代替功能测试。
8. 聚焦校验器：覆盖正例、非法配置、关键边界和至少一个组合回归。
9. 正式策略：首次关卡、频率、单关上限、允许模式、互斥表和难度成本。
10. 可通关模拟器：实现该机制真实状态转移、失败条件、回合时序和随机种子复现。
11. 生成输出：CSV、本地关、远程包、manifest、地图排期和文档同步。
12. 修改 `gameplay-src` 后运行 `npm run build:wechat-gameplay-code`，再校验生成包源码同步。

以上任一项缺失时，机制只能保留在隔离测试入口，不能加入批量生成随机池。

## 12. 自动验收清单

每个候选关必须同时满足：

1. 外层 schema、坐标系、关卡 ID、code 和必填字段正确。
2. 11/10 行宽、颜色字符、活动色数量和权重正确。
3. 普通棋盘顶部支撑、全图连通、占位率、六方向同色连通块上限 8 和顶行同色连续上限正确。
4. 单目标救援关的 90 格正六边形、中心保留格、同色块和中心邻圈正确。
5. 特殊实体 ID/坐标唯一，并落在 `.`。
6. 漩涡完整轨道、虫洞整段通道、繁殖初始空位、风眼出入口数量等结构约束正确。
7. 锁链严格按整行“一钥匙、多锁球”生成，没有普通球或其他特殊实体混入。
8. 附件只落普通球，同格不叠加；蜘蛛宿主和锁行合法；彩云六字段完整。
9. 模式字段互斥正确：限时、单目标救援、多目标救援、发射序列、广告道具和遮挡规则一致。
10. 收集目标有足够供给，分裂色与目标色一致，冰目标不超供给。
11. 发射数、目标分和星级线由当前公式/校准表产生且可通过真实状态模拟。
12. 同类特殊位置满足相邻关与五关窗口的去重规则。
13. 完整配置与紧凑包往返后业务字段逐项相等。
14. 本地、镜像、远程包、两个 manifest 和浮岛救援身份保持同步。
15. 所有聚焦校验、全量静态校验和通关模拟退出码均为 0。

批量生成应采用“生成候选—严格校验—模拟—接受”的拒绝重试流程。单关超过规定候选次数仍无合法结果时，必须终止整批且不发布半成品；禁止删减机关、放宽约束或沿用旧输出。

## 13. 数据回收与二阶段调参

静态校验和自动模拟只能证明配置满足当前程序合同，不能替代真实玩家数据。上线候选批次必须保存：

- 生成器提交版本、CSV 哈希、参考轮廓哈希和包 manifest 版本。
- 每关布局签名、特殊位置签名、模式、目标、发射数、模拟种子和模拟结果。
- 通关率、平均/中位剩余发射数、失败原因、道具使用率、重试次数和平均时长。

调整难度时应修改统一策略、校准表或明确的逐关设计表后重新生成。禁止直接手改 compact 包或只改星级线来掩盖不可通关结构。
