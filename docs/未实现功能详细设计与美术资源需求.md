## 2. 全功能共同实现合同

### 2.1 配置原则

1. 每种对象使用明确的英文 `entityType` 或独立模式字段，不把多个机制塞进无约束的随机字符池。
2. 必填字段缺失、类型错误、坐标越界、资源不存在、模式冲突时直接抛错。
3. 新实体必须同步扩展运行时 Loader、离线 validator、compact codec、编辑器导入导出、道具说明、资源预加载和专项测试。
4. 会改变胜负条件的对象必须使用独立 `levelType`，不得仅作为普通特殊球投放。
5. 会占多个格子的对象必须保存完整占位模板或锚点与确定性展开规则，禁止运行时猜测形状。
6. 参考项目的 `r` 随机对象能力不得直接照搬；若启用，随机池必须显式列出类型、权重和模式白名单。

### 2.2 发射后阶段顺序

新增机制必须进入显式阶段队列，并在整个队列结束前锁定输入。建议顺序如下：

1. 发射球碰撞、吸附或特殊命中。
2. 普通匹配、冰层/护盾等一次性防护处理。
3. 范围清除、目标对象触发及即时失败检查。
4. 第一次支撑扫描和悬空掉落注册。
5. 漩涡/海星轨道旋转。
6. 虫洞通道移动。
7. 单球迷雾、全屏风沙和额外墨汁计数。
8. 地雷倒计时。
9. 感染扩散。
10. 变色机关换色。
11. 蜘蛛锁行状态更新。
12. 繁殖球生成。
13. 藤蔓魔灵施法。
14. 棋盘视口移动、危险线、胜负与结算。

任一阶段改变棋盘结构后，必须在进入下一结构型阶段前重新计算支撑；不得把本回合产生的悬空球留到下一发处理。

### 2.3 通用美术规格

- 普通单格球体优先提供透明 PNG；简单球体可参考 `stone_ball.png` 的 72×72 可见尺寸，含外溢光效、动画或遮罩的对象使用 140×140 透明画布并保持中心点一致。
- 棋盘对象资源建议放在 `assets/game/image/ball/<feature>/`；只有单张静态图时可放在 `assets/game/image/ball/`。
- 局内道具放在 `assets/game/image/props/`，弹窗/准备界面副本放在 `assets/ui/image/props/` 或 `assets/ui/image/preview_balls/`，禁止 UI 长生命周期引用可释放的 `game` SpriteFrame。
- 序列帧放在 `assets/game/animation/<feature>/`；全屏或材质特效放在 `assets/game/effects/`。
- 音效放在 `assets/audio/sound/`，建议统一使用功能英文名，例如 `mine_warning.mp3`。
- 所有资源必须有 `.meta`；需要稳定 UV 的自定义 Shader 图片设置 `packable: false`。
- 只有确实依赖原始画布对齐的叠层资源使用 `trim=false`，并通过暗色/亮色背景检查透明边缘。

**玩法规则**

- 旋转结束后立即执行支撑扫描；新形成三连不自动消除。

- 旋转造成的悬空球在本次发射周期立即掉落。

### 3.2 参考版多目标救援

**定位**

当前 `trapped_sprite_rescue` 是中心精灵支撑玩法，不能改造成参考版。新增 `levelType: "multi_target_rescue"`，保留现有 50 个中心精灵救援关不变。

**配置建议**

```json
{
  "levelType": "multi_target_rescue",
  "rescueTargets": [
    {"id": "rescue_01", "row": 6, "col": 4, "spiritId": "milu"}
  ],
  "winConditions": [{"type": "rescue_all_targets", "value": 1}]
}
```

- 目标格必须是 `.`，不得位于第 0 行。
- 每个目标至少有一个初始可消除的相邻支撑路线。
- 一关 1～5 个目标，ID、坐标唯一。

**玩法规则**

- 落点邻接目标时，即使没有三连也可解救，并把本次行为视作有效消除。
- 普通消除和范围效果触达目标时转交救援逻辑，目标不进入普通爆炸列表。
- 最后一个目标解救后锁定输入、停止后续普通爆炸表现、清理剩余棋盘并进入胜利。
- 解救对象不加入精灵大厅解锁链，除非配置显式声明 `unlockSpirit: true`。

**所需美术**

- `assets/game/image/ball/rescue_target/<spiritId>.png`：七名精灵的单格被困头像或笼中小图，建议 140×140。
- `assets/game/animation/rescue_target/free_<spiritId>.anim`：解救离场动画，可共用路径和粒子模板。
- `assets/game/image/effect/rescue_glow.png`、`rescue_trail.png`。
- UI预览副本：`assets/ui/image/preview_balls/rescue_target.png`。
- 音效：`rescue_target_hit.mp3`、`rescue_target_free.mp3`、`rescue_all_complete.mp3`。

**验收**

- 非救援关拒绝 `rescueTargets`。
- 最后目标只结算一次，不与普通爆炸或掉落胜利重复触发。
- 普通命中、炸弹命中、悬空断支撑三条解救路径均有专项用例。

### 3.3 限时模式补行与 Fever

**配置建议**

在现有 `timed_infinite_shots` 上增加必填的 `timedRules`：

```json
{
  "timedRules": {
    "rowSegmentStarts": [0, 10, 20],
    "visibleRowLimit": 10,
    "refillAtOrBelowRows": 10,
    "feverBlastComboRemainder": 4,
    "feverLightningComboRemainder": 9,
    "feverModulo": 11
  }
}
```

**玩法规则**

- 当前可见占用行不超过阈值时，从尚未使用的候选段中按关卡种子选择一段补到顶部。
- 每个段只能使用一次；没有剩余段时继续清理现有棋盘。
- 连击模 11 等于 4 时下一球转换为二圈炸弹，等于 9 时转换为贯底闪电。
- Fever 球不消耗道具库存，但仍计一次发射；连击清零立即结束 Fever 表现。
- 超时继续按现有一星门槛判胜负，加时球仍固定增加 5 秒。

**所需美术**

- `assets/game/image/hud/fever_bar_bg.png`、`fever_bar_fill.png`、`fever_label.png`。
- `assets/game/image/effect/fever_burst.png`、`fever_ball_change.png`。
- Fever 炸弹/闪电复用对应特殊发射球资源。
- 音效：`fever_start.mp3`、`fever_ball_ready.mp3`、`timed_row_refill.mp3`。

**验收**

- 相同关卡种子得到相同补行顺序。
- 补行后碰撞、支撑和加时球坐标同步迁移。
- 暂停、弹窗和切后台期间倒计时及补行状态不推进。

### 3.4 通配彩虹与超级彩虹

**配置建议**

- 保留当前 `rainbow` 选色道具语义，命名为 `selectable_rainbow`。
- 新增发射球 `wildcard_rainbow` 与 `super_rainbow`，禁止用同一 `entityType` 隐式切换行为。

**玩法规则**

- `wildcard_rainbow` 命中后扫描所有相邻普通色分支；能够形成至少 3 球的分支全部进入候选，按稳定颜色顺序合并清除。
- 若没有任何可清除分支，彩虹原地转为相邻普通色；无相邻普通色时按当前棋盘色权重确定颜色。
- `super_rainbow` 只保留候选中数量最大的一个颜色组；数量相同按 `level.colors` 顺序决胜。
- 锁球、护盾、感染球和不可匹配对象不进入颜色组。

**所需美术**

- 复用现有彩虹球作为 `selectable_rainbow`。
- `assets/game/image/ball/wildcard_rainbow.png`、`super_rainbow.png`，各 140×140。
- `assets/game/effects/RainbowAssimilation.effect`：颜色吸附流光。
- UI副本各一张；音效 `rainbow_wildcard.mp3`、`rainbow_super.mp3`。

**验收**

- 无三连时不会无结果消耗彩虹球。
- 超级彩虹只清除一个最大颜色分支。
- 同一棋盘与种子结果确定，不依赖对象遍历顺序。

### 3.5 整行锁链

**定位**

保留现有钥匙与单个锁定球配对机制，新增独立 `lock_line` 机关，避免改变已有关卡。

**配置建议**

```json
{
  "lockLines": [{
    "id": "lock_line_01",
    "row": 6,
    "keyCells": [{"row": 6, "col": 2}, {"row": 6, "col": 7}]
  }]
}
```

**玩法规则**

- 锁线以上的球标记为 `isLineLocked`，不能匹配、变色、感染或被普通特殊清除。
- 钥匙必须通过正常消除、范围命中或悬空掉落被移除。
- 最后一把钥匙移除后整条锁链解除；同一球存在其他锁线时仍保持锁定。
- 漩涡轨道触及锁定区时按配置阻断，不允许带着锁线移动。

**所需美术**

- `assets/game/image/ball/lock_line/key_ball.png`：可复用现有钥匙主体。
- `chain_horizontal.png`、`chain_joint.png`、`chain_locked_overlay.png`。
- `assets/game/animation/lock_line_break/`：断链序列帧 6～10 帧。
- 音效：复用 `lock_open.mp3`，新增 `lock_chain_hit.mp3`。

**验收**

- 多锁线叠加时引用计数正确。
- 最后一把钥匙前不得提前解锁。
- 解锁只改变权威锁状态，不通过换材质伪装可操作性。

### 3.7 普通闪电与贯底闪电发射球

**配置与道具**

新增 `skill_ball/lightning`、`skill_ball/deep_lightning`；发射前替换当前球，分别沿入射方向对应的六边形斜线清除最多 5 行或直到棋盘边界。

**玩法规则**

- 第一接触格决定主斜线，不能使用屏幕像素近似选择方向。
- 每格按距离顺序结算；冰层先破冰，锁定对象跳过，目标对象转交专用处理。
- 贯底闪电遍历完整逻辑棋盘，包括当前视口外的行；普通闪电最多 5 行。
- 与精灵 `lightning_chain` 使用不同事件和资源，不共享目标选择算法。

**所需美术**

- `lightning_ball.png`、`deep_lightning_ball.png`。
- 可复用 `assets/game/image/skill/lightning/` 的电弧纹理；新增直线导向箭头与贯底加强尾迹。
- UI道具图两张；音效 `lightning_shot.mp3`、`deep_lightning_shot.mp3`。

**验收**

- 奇偶行边界、左右斜线、视口外清除和冰/锁/目标转交均有测试。

## 4. 棋盘特殊球详细设计

### 4.1 骷髅/蜜蜂球

**配置**：新增 `hazard_ball/bee_skull`，可选 `shieldItemId: "bee_shield"`，禁止顶行密集连排。

**规则**：发射球吸附且本次没有形成有效消除时，若六邻格存在该对象，按距离、行、列选择一个威胁触发；有防蜂罩则消费一次并解除本次失败，无防护则进入 `lost_hazard`。对象可被范围清除或悬空掉落；感染覆盖前应先把它转成配置指定普通色。

**美术资源**：`bee_skull_ball.png`、`bee_skull_warning.png`、蜜蜂飞出/蜇击 8～12 帧、`bee_shield.png`、`bee_shield_break.png`；UI预览图；`bee_warning.mp3`、`bee_sting.mp3`、`bee_shield_break.mp3`。

**验收**：有效消除不触发、无效落球只结算一个威胁、防护只消费一次、失败状态不会继续推进其他回合机制。

### 4.2 地雷

**配置**：新增 `hazard_ball/mine`，必填 `initialLife`，建议 2～9；禁止使用缺省生命。每个地雷独立保存剩余生命和是否已经暴露。

**规则**：六个有效邻位未全部被占用后进入暴露状态；暴露后的每次真实发射结束生命减 1。生命为 0 时立即锁输入并进入 `lost_hazard`。被消除或掉落后停止计时。漩涡、虫洞改变邻位后必须重新判断首次暴露。

**美术资源**：`mine_ball.png`、`mine_exposed.png`、红色警告环、爆炸中心/烟尘序列；倒计时数字优先使用现有 BMFont；`mine_tick.mp3`、`mine_warning.mp3`、`mine_explode.mp3`。

**验收**：未暴露不减生命；多个地雷稳定顺序结算；清除与归零同帧时以先完成的权威移除结果为准，不能既清除又失败。

### 4.3 随机鱼卵

**配置**：新增 `reactive_ball/fish_egg`，必填确定性 `outcomeWeights`、`firstTriggerOutcome` 和 `inkDurationShots`。正式生成器不得依赖运行时 `Math.random`。

**规则**：邻接有效消除或悬空掉落触发；有冰时第一次只破冰。打开后按关卡种子生成墨鱼、大嘴鱼或染色鱼。墨鱼添加持续 5 发的额外墨汁；大嘴鱼选择左/右并吃掉同一行对象；染色鱼沿一个方向依次把普通球改成棋盘现有颜色。关键目标、锁定球和固定支撑对象必须被过滤。

**美术资源**：鱼卵完整/裂开各一张；墨鱼、大嘴鱼、染色鱼各一套游出与施法动画；墨汁覆盖、吃球轨迹、染色波纹；UI预览；`fish_egg_crack.mp3`、三种鱼各一条施法音效。

**验收**：同一种子分支和方向一致；首次强制分支只执行一次；三分支均正确触发支撑扫描。

### 4.4 风眼系统

**配置**：入口使用独立 `windEye` 对象，出口使用 `reactive_ball/wind_eye_exit`，至少两个出口；必填 `switchIntervalSeconds` 和确定性出口顺序种子。

**规则**：发射球进入入口后停止原轨迹、缩小、迁移到当前激活出口，再从出口方向继续执行碰撞。球停靠到出口格或出口失去支撑时移除该出口；全部出口移除后入口关闭。出口可穿越但不可普通匹配。

**美术资源**：入口漩涡底图、Shader噪声图、出口激活/未激活图、出口方向箭头、吸入/吐出轨迹；UI预览；`wind_eye_switch.mp3`、`wind_eye_enter.mp3`、`wind_eye_exit.mp3`。

**验收**：传送后仍使用权威连续轨迹；出口周围没有合法落点的配置直接拒绝；切后台不改变当前出口。

### 4.5 圣诞礼盒

**配置**：新增 `activity_ball/gift_box`，必填 `activityId` 和服务返回的 `rewardPoolVersion`；没有活动服务和非空掉落表时配置加载失败。

**规则**：邻接命中、范围命中或悬空掉落转交礼盒逻辑；带冰先破冰。打开后移除礼盒、记分并从已经在开局锁定的奖励池抽取一个物品，禁止触发时临时请求服务。

**美术资源**：礼盒关闭/受击/打开、奖励光束、通用物品飞入 HUD 轨迹；活动预览图；`gift_hit.mp3`、`gift_open.mp3`、`gift_collect.mp3`。

**验收**：无服务数据阻断开局；断网不生成空奖励；同一礼盒只能领取一次。

### 4.6 积雪球

**配置**：新增 `reactive_ball/snowball_pile`，必填底部候选罐位规则和生成雪罩的耐久。

**规则**：邻接有效命中后移除并在横向最近的可用罐位生成雪罩；已有普通保护罩的边缘位置不可选。有冰时先破冰。雪罩拦截掉落球并按耐久破碎。

**美术资源**：积雪球完整/受击、雪球飞向底部轨迹、五个罐位适配的雪罩或一张可缩放九宫格、破碎碎片；UI预览；`snowball_pile_break.mp3`、`snow_cover_land.mp3`、`snow_cover_break.mp3`。

**验收**：罐位选择确定；没有合法罐位时配置或触发前置检查直接报错；保护罩与雪罩不得视觉重叠。

### 4.7 透明穿透球

**配置**：新增 `reactive_ball/transparent`，必填 `penetrationRemovalScore`。

**规则**：发射轨迹首次穿过时移除透明球并继续飞行，不在该格吸附；有冰时仅破冰并停止本次穿透移除。仅破坏透明球也视作有效命中，执行掉落检查并保留连击。透明球后方必须存在可到达的合法终点区域。

**美术资源**：半透明玻璃球、折射高光、破碎序列、穿透波纹；UI预览；`transparent_pass.mp3`、`transparent_break.mp3`。如使用折射 Shader，提供稳定 UV 噪声图并设置 `packable: false`。

**验收**：高速飞行不重复触发；轨迹预测与真实穿透路径一致；破坏后仍能命中后方对象。

### 4.8 染色蛋

**配置**：新增 `reactive_ball/dye_egg`，必填可染色半径，首版固定六邻格。

**规则**：邻接命中后在原格孵化普通球；普通色发射球决定颜色，特殊发射球按当前棋盘权重确定颜色。周围普通球改成同色，但锁定、感染、护盾和关键对象不变。染色本身不立刻触发三连，等下一正常匹配或专门规则处理。

**美术资源**：染色蛋完整/裂纹/孵化 8～12 帧、八色染色波纹可通过一张白色素材运行时着色；UI预览；`dye_egg_hit.mp3`、`dye_wave.mp3`。

**验收**：特殊球命中也能确定颜色；改色不覆盖附着状态；漩涡移动后孵化坐标准确。

### 4.9 幽灵中心对象

**配置**：仅允许在 `levelType: "free_ghost"`，新增 `mode_anchor/ghost`，一关恰好一个；必填 Box2D 场景参数和辅助布局。

**规则**：胜利条件为幽灵六邻格全部为空；幽灵本体免疫普通范围清除。普通场景中的染色命中行为不进入首版，避免与专用胜负路径混用。

**美术资源**：幽灵待机、受击、获救/搭桥胜利动画；中心碰撞提示圈；专用场景背景和桥；UI模式图标；`ghost_hit.mp3`、`ghost_rescued.mp3`。

**验收**：普通关拒绝幽灵；幽灵本体不能掉落或被炸掉；六邻清空只触发一次胜利。

### 4.10 黑洞

**实现状态（2026-08-15）**：核心玩法、容量、直接吞弹、范围卸载、回合推进、关卡压缩协议、测试关三发预算与静态资源渲染已实现；旋转 Shader、容量环、吸入/关闭演出与专用音效仍待美术资源补齐。

**配置**：新增 `hazard_ball/black_hole`，必填 `capacity: 3`，禁止生成器省略。

**规则**：第一次直接接触吞掉发射球，不吸附、不匹配，但推进完整回合。每吞一球容量减 1，第三球后黑洞移除并重算支撑。范围特殊效果直接关闭黑洞；锁定状态下不能吞球。

**美术资源**：黑洞底图、旋转 Shader、容量 3/2/1 三态环、吸入缩放轨迹、关闭爆闪；UI预览；`black_hole_swallow.mp3`、`black_hole_close.mp3`。

**验收**：吞球仍推进地雷、感染等阶段；容量持久化到运行时快照；一帧内不能吞两次。

### 4.11 繁殖球

**配置**：新增 `hazard_ball/breeder`，必填 `spawnEveryShots: 1` 和 `spawnColorPolicy: "board_colors"`。

**规则**：发射结束时从六邻空位按稳定顺序和关卡种子选一个，生成当前棋盘已有普通色。若本回合邻近格发生爆炸则跳过。周围没有空位时不改色、不补偿生成。新增球后执行支撑与危险线检查。

**美术资源**：繁殖球待机脉冲、生成前预告、幼球弹出轨迹；UI预览；`breeder_ready.mp3`、`breeder_spawn.mp3`。

**验收**：满邻位无动作；爆炸邻域本回合不回填；多个繁殖球按 ID 顺序且不能抢占同一格。

### 4.12 城堡头与主体

**配置**：新增多格 `castleStructure`，保存模板 ID、头部锚点、主体格列表、Boss 配置 ID；禁止以两个独立特殊球随机投放。

**规则**：主体参与支撑但不普通匹配；城堡头免疫范围清除。支撑断裂时整个结构进入专用掉落和开笼/开宝箱流程，强制完成 Boss 目标。结构中任一必填格缺失时关卡加载失败。

**美术资源**：城堡头、主体连接块、笼子/宝箱、锁、掉落拖尾、开笼/开箱动画、Boss受击层；根据模板提供偶数/奇数行拼接版本；模式预览图和三条音效。

**验收**：模板展开无重叠；范围效果不能直接清头；断支撑后整组只结算一次。

### 4.13 受控随机对象池

不实现参考项目无约束 `r`。若产品确认需要，配置必须为：

```json
{
  "randomEntityPools": [{
    "id": "pool_01",
    "allowedTypes": ["stone", "transparent"],
    "weights": [70, 30],
    "seedScope": "level_attempt"
  }]
}
```

对象在开局时一次性确定，回放和重试种子可复现；会改变胜负条件、依赖活动服务或专用场景的对象永远禁止进入通用池。美术只需要通用随机预告叠层 `random_entity_mark.png` 和揭示动画，实际主体复用被选对象资源。

### 4.14 保留类型 17/18、WOOD

这些对象在参考代码中没有完整处理器，不进入实现排期。若以后恢复，必须先取得原始语义、配置样本和资源，再分别建立新 `entityType`；不得用占位图、普通球或默认行为兜底。当前所需资源清单无法可靠确定，产品评审状态为“阻断”。

## 5. 附着机关详细设计

### 5.1 单球迷雾/树叶

**配置**：新增 `level.cellAttachments`，每项包含 `id/type/row/col`；`type` 为 `fog` 或 `leaf`。附着目标必须是可显示的棋盘对象。

**规则**：只遮挡目标球，不影响碰撞和支撑；目标移动时附件按坐标状态一起迁移。芭蕉扇临时吹散全部迷雾，6 次真实发射后仍存活的附件恢复。目标移除时附件永久删除。

**美术资源**：单球云雾与树叶叠层各一张 140×140，吹散粒子、恢复聚合动画；UI预览；`fog_clear.mp3`、`fog_restore.mp3`。

**验收**：漩涡迁移、虫洞移动、掉落和节点复用后附件均不串位。

### 5.2 毒

**配置**：附件 `poison`，必填 `particleCount: 3`；只能附着到允许产生掉落粒子的对象。

**规则**：目标通过正常匹配清除时生成 3 个向下物理毒液；悬空掉落、感染覆盖或强制卸载不生成。毒液命中固定精灵使其离场；防毒网拦截同一批毒液后消失。

**美术资源**：毒液附着叠层、三种随机外形毒滴、飞溅粒子、防毒网受击效果；UI预览；`poison_release.mp3`、`poison_hit_spirit.mp3`、`poison_net_hit.mp3`。

**验收**：只在规定移除原因生成；批次 ID 明确；离开局内后无残留物理节点。

### 5.3 感染

**配置**：附件 `infection`，必填扩散方向策略，首版固定 `downward_right_priority`。

**规则**：每次发射后从有合法下方邻居的感染源中稳定选源，再感染一个目标。锁定源和锁定目标都不可用。覆盖时清除冰、迷雾、毒、冰凌、变色等附件；骷髅按明确配置先转普通色。感染球不参与普通三连。

**美术资源**：感染覆盖层、扩散触手、目标被覆盖动画、感染解除碎片；UI预览；`infection_spread.mp3`、`infection_clear.mp3`。

**验收**：多源选择确定；覆盖清理附件无孤儿节点；感染与地雷/繁殖组合必须通过回合模拟。

### 5.4 额外墨汁

额外墨汁只由鱼卵墨鱼分支生成，不允许独立关卡字段。它使用独立 `extraAttachment` 槽，可与一个主附件共存；持续 5 次真实发射后删除。目标被鱼卵、透明球等专用触发移除时先清理墨汁。

**美术资源**：3～4种墨汁遮罩随机形态、淡出序列、UI不单独展示；`ink_splash.mp3`、`ink_fade.mp3`。

### 5.5 变色/极光

**配置**：附件 `color_change`；目标必须是普通球，且关卡至少两个活动颜色。

**规则**：每次发射后改为当前棋盘另一种普通色，按关卡种子和稳定目标顺序确定；动画进度约 60% 时提交权威颜色。感染覆盖或目标移除时取消未完成动画。

**美术资源**：白色可染色极光环、颜色过渡粒子、UI预览；`color_change.mp3`。

**验收**：不能改回原色；动画中暂停不提前提交；节点复用不保留旧色材质。

### 5.6 冰凌

**配置**：附件 `icicle`，必填 `fragmentCount: 3`。

**规则**：仅正常消除时生成 3 个冰凌碎块；悬空、感染和强制清理不生成。冰凌命中固定精灵使其离场；冰凌防护网只拦截冰凌批次。

**美术资源**：冰凌覆盖层、3种碎块、破碎粒子、冰凌防护网及受击动画；UI预览；`icicle_break.mp3`、`icicle_net_hit.mp3`。

**验收**：与毒液使用不同碰撞分组；两种防护网不可互换。

### 5.7 蜘蛛与蜘蛛茧

**配置**：新增 `spiderRows`，每个蜘蛛包含锚点坐标和锁行 ID；同排允许多个蜘蛛但必须显式配置。

**规则**：蜘蛛锁住整行；已有球添加蜘蛛锁，空位生成不可发射的 `spider_cocoon`。被锁球不匹配，范围清除按最底层蜘蛛规则过滤。移除一个蜘蛛只减少一层锁；最后一个蜘蛛移除后解除整行并删除对应茧。

**美术资源**：蜘蛛本体待机/受击、蛛网锁层、蜘蛛茧、整行拉网动画、解锁断丝粒子；UI预览；`spider_lock.mp3`、`spider_break.mp3`。

**验收**：多蜘蛛引用计数正确；行宽 11/10 都能补齐；漩涡轨道遇锁行按阻断合同处理。

### 5.8 气泡护盾/棉絮

**配置**：附件 `bubble_shield`，每个球最多一层。

**规则**：底层球不能普通匹配；相邻位置形成正常消除或特殊效果触达时先移除护盾，底层球是否继续被同次范围清除由效果合同显式决定。随机鱼、礼盒、积雪球等关键对象禁止初始附盾。

**美术资源**：透明护盾球壳、棉絮版本、受击裂纹、爆裂粒子；UI预览；`bubble_shield_hit.mp3`、`bubble_shield_break.mp3`。

**验收**：一次命中只扣一层；护盾存在时颜色搜索排除底层球；移除后 Sprite 和材质完全释放。

## 6. 场景特殊物详细设计

### 6.1 乌龟/瓢虫

**配置**：独立 `movingObstacles` 数组，包含 `kind/startTime/duration/speed/side/stunSeconds`，所有数值必填。

**规则**：到时从指定侧游入，结束后离场。乌龟碰发射球使球爆掉并清空连击；瓢虫按入射角决定掉落或反射。海草道具眩晕全部活动对象，口袋道具移除一个稳定选中的对象。

**美术资源**：乌龟和瓢虫游动、眩晕、离场动画；碰撞火花、方向阴影；UI预览；游入、碰撞、眩晕、收入口袋音效。

**验收**：轨迹预测包含移动碰撞体；暂停时移动和存在时间停止；销毁后不再接收碰撞。

### 6.2 彩云

**配置**：移动对象 `color_cloud`，必填颜色、开始时间、速度、消失命中次数和方向；彩虹云使用独立枚举，不使用数字 12。

**规则**：飞行球穿过时立即变为云颜色；每次穿过增加计数，到阈值后淡出。彩虹云把球转为通配彩虹，而不是随机普通色。

**美术资源**：普通白云主体、八色运行时着色遮罩、彩虹云、命中闪光和淡出粒子；UI预览；`color_cloud_pass.mp3`、`color_cloud_disappear.mp3`。

**验收**：同一发射球不能在一次穿越中重复计数；变色后轨迹和碰撞不中断。

### 6.3 全屏风沙/雪雾

**配置**：独立 `screenOcclusionEvents`，保存开始时间、两行范围、视觉类型和固定 5 次发射清理份额；与当前 `boardOcclusionPlan` 互斥。

**规则**：开始时间不低于 6 秒；地图移动和望远镜观察期间延迟出现。覆盖随机连续两行，每次发射移除约五分之一，覆盖行无球时立即消失，芭蕉扇可全部清除。

**美术资源**：风沙和雪雾各 3～5 块可拼接前景、吹散粒子、遮挡倒计时提示；UI预览；`sandstorm_start.mp3`、`sandstorm_clear.mp3`。

**验收**：只遮视觉不改碰撞；五阶段移除稳定；不能与当前区域遮挡重复覆盖同一玩法关。

### 6.4 底部普通保护罩

**配置**：局内道具生成，不进入关卡静态对象；耐久固定 30 次，可配置左右两侧碰撞面。

**规则**：拦截掉落普通球并减少耐久；毒液、冰凌和其他专用粒子不由该罩处理。耐久归零淡出。与雪罩争用位置时普通保护罩优先。

**美术资源**：左右保护罩、受击裂纹 3 阶段、碰撞闪光、淡出；道具图；`bottom_shield_hit.mp3`、`bottom_shield_break.mp3`。

**验收**：耐久只由合法掉落球扣除；重开关卡清零；保护罩节点位于罐子前景但不遮挡 HUD。

### 6.5 雪罩

雪罩由积雪球生成，按罐位保存 `slotIndex/durability/sourceId`。它只拦截掉落球，破碎后恢复该罐位。资源和积雪球联动见 4.6；必须验证五个罐位的尺寸、锚点和原始画布对齐。

### 6.6 毒液防护网与冰凌防护网

两种网分别为 `poison_net` 和 `icicle_net`，拥有独立碰撞分组和当前批次 ID。放置后只接住下一批对应粒子，批次全部结束后播放命中并消失；没有目标批次时不允许使用。

**美术资源**：两张颜色和轮廓明显不同的网、展开动画、粒子命中闪光、道具图；分别提供放置和命中音效。

**验收**：交叉粒子穿过；库存只在放置成功后扣除；同一网不会跨批次常驻。

### 6.7 圣诞老人/丘比特与雪屋

**配置**：专用 `escortActivity`，包含活动类型、角色起点、三球支撑组、雪屋三格锚点和活动服务版本。

**规则**：角色在支撑三球仍存在时逐行向雪屋移动；支撑组或雪屋三格断裂时触发专用掉落与活动胜负。普通 `clear_all` 不作为胜利条件。

**美术资源**：圣诞老人和丘比特行走/待机/掉落/胜利动画；雪屋三格拼接资源、雪屋受击和坍塌；活动背景装饰、模式图标及完整音效组。

**验收**：活动服务、资源、ID范围任一缺失均阻断开局；三格模板不得越界；活动结算只提交一次。

## 7. 主玩法模式详细设计

### 7.1 推行/下压模式

**配置**：新增 `levelType: "pressure_push"`、`playMode: "timed_board_pressure"`，必填 `fastIntervalSeconds/slowIntervalSeconds/rowThreshold/warningY/failY/pushUpItemRows`。

**规则**：占用行大于 5 时每 5 秒下移一行，否则每 4 秒下移一行；动画、弹窗、切后台和特殊阶段锁定期间计时暂停。最低球越过警告线显示提示，越过失败线进入 `lost_danger`。道具可向上推 3 行。

**美术资源**：危险线普通/警告态、棋盘下压箭头、震屏尘土、上推道具及三行上升轨迹、模式图标；警告、下压、失败音效。

**验收**：真实时间与动画阻塞计入同一权威时钟；最短解模拟在理论触底前完成；普通关拒绝下压参数。

### 7.2 怪物模式

**配置**：新增 `levelType: "monster_battle"` 和独立 `monsterConfigId`；怪物配置包含生命、阶段阈值、技能序列、猫技能颜色与蓄力阈值。

**规则**：一星分数可作为生命基准，但必须在生成时固化。普通爆炸和入罐得分造成伤害；指定颜色先为猫技能蓄力。生命跨阈值时按顺序施放石化、骷髅、感染、冰或迷雾技能。生命为 0 后进入胜利，不能继续发射。

**美术资源**：每只怪物待机/受击/四阶段技能/失败动画，生命条、技能预告、猫技能蓄力图标、模式背景和完整音效；至少需要一只首发怪物的全套资源。

**验收**：配置和关卡 ID 不硬编码；跨多个生命阈值时技能按序不丢失；伤害、分数和结算一致。

### 7.3 城堡 Boss 模式

**配置**：新增 `levelType: "castle_boss"`，引用城堡模板和 Boss 配置，不以关卡 ID 大小推断。

**规则**：目标是断开城堡支撑使其掉落并开笼/开箱；头部免疫范围清除。打开后按配置授予结算分，不建议无条件强制三星，除非产品明确保留参考规则。

**美术资源**：见 4.12，另需 Boss HUD、模式入场、胜利开箱和奖励展示。

**验收**：怪物模式和城堡模式互斥；完整模板与胜负链专项验证。

### 7.4 自由幽灵模式

**配置**：新增 `levelType: "free_ghost"`，必须切换专用物理场景或明确的 Box2D 子系统；一关恰好一个幽灵中心。

**规则**：胜利只由幽灵六邻清空决定；不初始化固定精灵、乌龟、风沙和彩云。普通顶部支撑和清空全图规则关闭。

**美术资源**：见 4.9；还需专用场景边界、桥与角色胜利演出。

**验收**：场景切换、资源释放、专用碰撞和胜负条件在微信真机验证。

### 7.5 节日护送模式

**配置**：新增 `levelType: "holiday_escort"`，显式活动类型，不使用关卡 ID 范围识别。

**规则与资源**：见 6.7。该模式必须依赖活动服务和资源完整性检查，未接服务前不得进入生成器或正式关卡。

## 9. 自动生成、模拟和报告能力

### 9.1 沙盒候选批次生成器

在现有正式 1～1000 关生成器之外新增 `tools/generate-level-candidates.js`，不得替换或直接覆盖正式关卡。参数至少包含：

- `--count`
- `--seed`
- `--start-id`
- `--difficulty-tier`
- `--level-type`
- `--output-dir`
- `--validate <file>`

输出：

- `候选关卡.json`
- `生成报告.json`
- 固定生成器版本、批次种子、逐关接受种子、重试次数、结构指标、模拟指标和拒绝原因。

同版本、同参数、同种子必须产生字节级一致结果。最多尝试 400 个派生种子，全部失败时终止整个批次，不写半成品。

### 9.2 专项模拟器

每种 B/C 级机制进入正式生成器前必须具备局面转移模型：

- 地雷：暴露与倒计时失败。
- 黑洞：额外三发预算和吞球后的阶段推进。
- 繁殖：空位增长、危险线和爆炸跳过。
- 感染：传播方向、覆盖附件和可切断性。
- 蜘蛛：锁行、茧占位和可解锁路径。
- 移动物：时间轴、碰撞和道具干预。
- 限时：单位时间发射、补行、加时与 Fever。
- 下压：真实时间、动画阻塞和触底线。
- 怪物/Boss/幽灵/活动：各自专用胜负模拟。

模拟器不支持某机制时必须明确报 `unsupported mechanic`，不得把该关按普通球模拟后给出虚假通关结论。

### 9.3 正式生成接入

每项功能必须按以下顺序接入：

1. 完成运行时和专项测试关。
2. 完成 Loader、codec、编辑器、资源和 validator。
3. 完成专项模拟器。
4. 在 `campaign-level-generation-config.js` 定义首次教学关、投放节奏、阶段上限和互斥矩阵。
5. 通过权威生成器重建 CSV、本地关、远程包和 manifest。
6. 运行全量关卡内容校验、compact 往返、专项 validator、玩法 bundle 和代表性模拟。

## 11. 明确阻断与非首发项

- `r` 无约束随机池：禁止实现；只能使用受控显式池。
- type 17/18、WOOD：语义和资源不完整，阻断。
- 圣诞礼盒和节日护送：活动服务与掉落表未完成前阻断。
- 城堡 Boss、怪物、自由幽灵：专用资源、胜负系统和模拟器未完成前不得进入普通生成器。
- 参考版多目标救援不得替换现有 `trapped_sprite_rescue`。
- 现有 `compact-schema-v2` 若无法让旧客户端安全拒绝新字段，应建立新格式/新远程路径，不得让旧客户端误读热更新关卡。

## 12. 文档验收清单

- 每个缺失或规则未补齐功能均有独立配置入口或明确复用入口。
- 每项均说明权威状态、触发时机、阶段顺序和胜负/支撑影响。
- 每项均列出至少一组局内美术资源；需要 UI、特效、音效时已分别列出。
- 所有新功能都包含 Fail-Fast 校验要求，没有默认值、静默跳过或 mock 数据。
- 正式生成接入均以运行时、编辑器、codec、专项模拟器和完整校验链为前置条件。
