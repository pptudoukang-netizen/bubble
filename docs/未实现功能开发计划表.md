# 未实现功能开发计划表

## 1. 计划口径

- 关联设计：[未实现功能详细设计与美术资源需求](./未实现功能详细设计与美术资源需求.md)。
- 估算单位：客户端程序人日；美术、动画、音频、策划配关、服务端和真机测试单独估算。
- 排期原则：每项按“配置合同 → 运行时 → 渲染资源 → 编辑器 → 生成/模拟 → 专项校验 → 玩法 bundle”的纵向切片完成。
- 开工限制：上一个切片没有完整验收前，不把该机制批量投放到正式关卡。
- 严格模式：不添加默认配置、旧格式兜底、空资源占位或异常吞噬。

## 5. 每项完成定义

单个功能只有在以下项目全部完成后才能标记“已实现”：

1. 设计合同和配置示例已确认。
2. Loader 与离线 validator 使用相同严格规则。
3. compact 编解码无损，远程包边界明确。
4. GameManager/BubbleGrid/System 完成权威状态结算。
5. LevelRenderer 只渲染快照，不建立第二套业务状态。
6. 美术、UI副本、特效、音频已导入并通过资源生命周期检查。
7. 地图编辑器可导入、编辑、保存和重新加载。
8. 专项测试关覆盖正常、边界、冲突和失败路径。
9. 专项 validator、`validate:levels`、`validate:level-pack-v2`、`validate:level-editor`、`validate:shots` 通过。
10. 修改 `gameplay-src` 后重新生成 `assets/game/generated/lazy-gameplay-code.js`，并通过 `validate:gameplay-bundle`。
11. 进入正式生成器前已有对应模拟器或明确的静态A级证明。
12. Cocos Preview和微信真机完成表现、碰撞、内存与包体检查。

## 6. 推荐首发范围

首发建议只选择以下六项：

1. 透明穿透球。
2. 二圈炸弹。
3. 普通/贯底闪电。
4. 消一行/消两行。
5. 同色清屏球。
6. 变色/极光附件。

它们对专用服务、Box2D、多角色动画和复杂活动状态依赖较少，也能复用当前炸弹、闪电链、棋盘行遍历、颜色资源和附件框架。首发完成后再根据实际通关率、道具使用率和失败原因决定是否进入地雷、黑洞、感染、蜘蛛等第二批机制。
