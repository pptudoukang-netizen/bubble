# 拯救被困精灵玩法设计

## 1. 文档状态

- 状态：首版玩法内核、运行时渲染、正式主线生成、测试关和专项验证已实现
- 适用项目：Bubble 泡泡龙局内玩法
- 玩法类型：以中心被困精灵为唯一支撑锚点的旋转泡泡棋盘
- 当前实现用精灵大厅同一组七名 `spiritId` 映射被困形象；关卡编辑器专用工具和受力弧线提示仍属于后续范围

### 1.1 当前实现落点

- 关卡类型：`trapped_sprite_rescue`。
- 权威旋转系统：`gameplay-src/systems/TrappedSpriteRescueSystem.js`。
- 测试关：`assets/map/config/levels/level_trapped_sprite_test.json`。
- 测试入口：选关页隐藏测试模式中的“精灵”按钮。
- 正式主线：每100关在章内第 `25/42/63/86/99` 关投放救援玩法，共50关，由统一生成策略确定性生成。
- 正式棋盘：中心锚点固定在第6行中央，外围严格使用六角距离1至5的完整正六边形，共90个占用槽位；中心到任一顶点均为5个球。普通球和特殊实体不得落在六边形外。
- 正式配色：普通球最大同色连通块为5；中心锚点六邻格按顺时针闭环统计，连续同色普通球不得超过2。特殊实体会中断该连续色段。
- 身份与美术映射：`spiritId` 只能是 `milu/lumi/noya/flora/loco/kelu/yumi`；局内严格加载 `game/trapped_spirit/{spiritId}`，地图 `landmark1/spirit` 严格加载 `map/image/trapped_spirit/{spiritId}`。
- 存档与大厅：普通主线救援关胜利后，将该关 `spiritId` 对应角色解锁为精灵大厅递球手；未解锁头像置灰，升级、出战只提示需要先完成对应救援关，不修改资源或精灵状态。
- 顶部规则：第0行不再提供支撑和吸附；发射球触碰顶部边界后反弹，只有球心运动到炮台位置以下才结算为 `miss` 并消失。
- 中心吸附：被困精灵占用的保留格是可命中的支撑点；发射球触碰精灵后不反弹，而是吸附到接触方向对应的精灵六邻空格。
- 支撑规则：只从被困精灵锚点的六邻格开始 BFS。
- 结构结算：有无同色消除都在同一发射周期扫描支撑并注册掉落。
- 渲染规则：泡泡仍保留 `row/col`，每帧从权威角度计算世界坐标；被困精灵节点固定在世界中心，并始终位于所有棋盘泡泡节点的上层。

## 2. 设计目标

### 2.1 核心目标

1. 被困精灵固定在棋盘中心，周围泡泡相互连接，所有有效支撑最终必须连通到被困精灵。
2. 完全移除普通棋盘依赖顶部行、锁定球或虫洞提供支撑的规则。
3. 发射泡泡吸附后，根据真实入射方向、命中位置到被困精灵的距离以及当前泡泡簇惯量，让受支撑泡泡围绕被困精灵产生受力旋转。
4. 泡泡簇可以停留在任意角度，后续瞄准、碰撞和吸附仍然保持准确。
5. 消除连接点后，无法连通被困精灵的泡泡必须在本次发射周期内立即进入正常掉落链路。
6. 旋转角度、支撑关系、吸附结果和胜负判定全部由玩法状态决定，渲染层不得建立独立结果。
7. 关卡配置、远程压缩包、编辑器和验证器保持 Fail-Fast，不通过默认值或兼容分支掩盖缺失配置。

### 2.2 非目标

首版不包含以下行为：

- 不模拟泡泡之间的弹簧、挤压或逐球刚体碰撞。
- 不让中心被困精灵随泡泡簇持续旋转或移动。
- 不把顶部边界作为可吸附表面。
- 不使用普通棋盘的顶部空槽崩塌、行推进和危险线规则。
- 不允许锁定球、虫洞成为额外支撑锚点。
- 不在旋转过程中重新排列泡泡的格子坐标。
- 不在运行时为缺失的被困精灵、旋转参数或锚点位置补默认值。
- 首版不支持一关多个被困精灵或多个独立旋转泡泡簇。

## 3. 核心玩法模型

### 3.1 被困精灵锚点

被困精灵占用一个保留的六边形格子。该格子只用于定义：

- 被困精灵的逻辑位置。
- 泡泡簇的旋转中心。
- 支撑搜索的根节点。
- 被困精灵视觉节点的定位。

被困精灵格不能放置普通泡泡或特殊实体，也不能成为发射泡泡的吸附目标。

被困精灵本体按一个泡泡碰撞直径参与发射球命中检测。命中后从锚点六邻格中选择最符合接触方向的合法空格吸附；精灵中心保留格本身仍不放置泡泡，也不参与颜色匹配。新吸附泡泡作为第一层支撑泡泡参与后续连通和旋转计算。

被困精灵周围六个相邻格为第一层支撑位。第一层泡泡继续支撑外层相邻泡泡，最终形成一张以被困精灵为根的六边形连接图。

示意：

```text
        ○ ○
      ○ ○ ○
    ○ ○ 🐾 ○ ○
      ○ ○ ○
        ○ ○
```

### 3.2 唯一支撑规则

被困精灵模式中的支撑种子只能来自被困精灵格的六个邻接格。

```text
seeds = 被困精灵六个邻接格中当前存在的泡泡
supported = 从 seeds 沿六方向泡泡连接执行 BFS
floating = 棋盘全部泡泡 - supported
```

规则：

- 棋盘第 0 行不提供支撑。
- 锁定球不提供支撑。
- 虫洞不提供支撑。
- 被困精灵格本身不进入泡泡列表。
- 普通球、允许进入被困精灵模式的障碍球和特殊球都按所在格参与连接。
- 被困精灵六个邻接格全部为空时，所有剩余泡泡均失去支撑。
- 每次棋盘结构发生变化后都必须执行被困精灵支撑搜索。
- 无支撑泡泡必须在当前发射周期内移除并注册掉落，禁止延迟到下一次发射。

### 3.3 刚体旋转

受支撑泡泡共享同一个旋转角度。泡泡之间的相对位置、六边形邻接关系和格子坐标保持不变。

每个泡泡仍然使用 `odd-r-hex` 的 `row/col` 作为权威拓扑坐标。旋转只改变局部棋盘到世界坐标的变换，不改变格子数据。

这样能够保证：

- 泡泡间距不会因浮点误差逐渐漂移。
- 同色匹配继续使用离散邻接关系。
- 支撑搜索不依赖当前视觉角度。
- 棋盘可停留在任意角度。
- 后续发射可以准确命中已经旋转的泡泡。

## 4. 坐标系统

### 4.1 局部坐标

继续使用现有 `BoardLayout` 计算每个 `row/col` 的原始六边形位置。

设：

```text
Pcell = 格子的原始六边形位置
Panchor = 被困精灵格的原始六边形位置
Plocal = Pcell - Panchor
```

`Plocal` 是泡泡相对被困精灵中心的局部坐标，在整个关卡中保持不变。

### 4.2 世界坐标

设被困精灵世界坐标为 `Psprite`，当前棋盘旋转角为 `θ`：

```text
Pworld = Psprite + Rotate(Plocal, θ)
```

所有玩法层几何查询必须读取该世界坐标，包括：

- 发射球与棋盘泡泡碰撞。
- 瞄准轨迹预测。
- 吸附候选格筛选。
- 爆炸和范围效果中心。
- 消除、碎裂和掉落起点。
- 引导、高亮和受力提示定位。

### 4.3 世界坐标转局部坐标

发射球碰撞点和入射方向需要转换到被困精灵局部坐标，才能继续使用六边形格子邻接规则：

```text
Plocal = Rotate(Pworld - Psprite, -θ)
Vlocal = Rotate(Vworld, -θ)
```

碰撞检测使用世界坐标，吸附格选择使用转换后的局部接触点和方向。

### 4.4 权威状态

玩法快照至少保存：

```text
trappedSpriteRescue.anchorCell
trappedSpriteRescue.worldCenter
trappedSpriteRescue.rotationAngleRad
trappedSpriteRescue.angularVelocityRadPerSec
trappedSpriteRescue.rotationPhase
trappedSpriteRescue.rotationRevision
```

渲染层只读取快照，不自行累加角度或根据动画结果回写玩法状态。

## 5. 发射、碰撞与吸附

### 5.1 发射期间的棋盘状态

只有在以下状态全部结束后才允许再次瞄准和发射：

- 上一次泡泡簇旋转。
- 匹配与特殊效果。
- 无支撑掉落注册。
- 仍会修改棋盘结构的延迟效果。
- 胜负结算。

发射球飞行期间泡泡簇保持当前角度，不继续自由旋转。这样能够保证瞄准预测、真实碰撞和吸附格一致。

### 5.2 合法吸附

发射泡泡的目标格必须满足：

- 目标格为空。
- 目标格不是被困精灵保留格。
- 目标格与一个当前受支撑泡泡相邻。
- 发射球从当前入射方向能够实际到达目标格。
- 目标位置与已有泡泡不存在重叠。
- 目标位置位于关卡允许的旋转半径内。

碰撞后先将接触点和方向转换到被困精灵局部坐标，再从被碰泡泡的六个邻接格中选择最符合接触法线的合法格。

运行时已预测出合法吸附格，但最终提交时没有合法吸附格必须直接报错，说明预测和真实碰撞算法不一致。禁止回退到顶部格或任意空格。

救援关的泡泡簇旋转后不再受初始 11/10 列矩形边界裁剪。只要弹道真实命中棋盘泡泡，就必须使用碰撞外侧对应的六边形邻格完成吸附；该邻格即使位于初始布局的最左、最右或最上外沿，也属于救援关的合法扩展格，并进入正常的消除、掉落和旋转结算。禁止把真实碰撞处理成 `blocked`、射失、撞击后消失，或改吸附到棋盘其他位置。

旋转后的棋盘仍须先按世界坐标识别瞄准线经过的合法夹缝；夹缝落点存在时优先吸附到该格。若先命中泡泡，则幽灵球和最终落点必须共同指向该碰撞泡泡的真实六邻格，保证预测与结算一致。

### 5.3 顶部反弹与炮台退出边界

被困精灵模式没有顶部吸附。

发射泡泡触碰棋盘顶部边界时必须按照水平法线反射，保留水平速度并反转垂直速度。顶部只参与弹道反弹，不提供支撑，也不产生吸附格。

如果发射泡泡经过顶部或左右墙反弹后仍未命中泡泡簇，并且球心位置继续运动到炮台发射点以下：

- 本次发射计为射失。
- 消耗一个发射球。
- 不增加棋盘泡泡。
- 不产生旋转冲量。
- 不执行顶部吸附或边界吸附。
- 结算完本次发射后恢复输入或判断球数耗尽。

发射球到达顶部、左右墙或其他高于炮台的位置时都不能直接消失。低于炮台位置是被困精灵模式唯一允许产生 `miss` 并移除发射球的空间条件。射失是明确的玩法结果，不是异常兜底。

### 5.4 边界反弹

支持左墙、右墙和顶部边界反弹。受力计算必须使用实际碰撞前的最终飞行方向，而不是最初瞄准方向。

被困精灵本体作为圆形吸附支撑碰撞体：碰撞半径与当前发射球对棋盘泡泡的预测碰撞半径一致。命中时立即结束飞行，从锚点六邻格中筛选空位、可达性和接触方向，选择合法吸附格；如果不存在合法六邻吸附格则直接报错，不允许反弹、穿透或吸附到中心保留格。

`TrajectoryPredictor` 输出的 `pathPoints` 是发射球移动的权威路径，执行阶段必须逐段直接使用这些坐标。禁止根据 `wallBounceCount` 重新推导路径，因为顶部反弹不是左右墙反弹，重建为左右墙序列会在炮台附近制造虚假的横向反弹。

因此反弹射击可以主动改变泡泡簇的旋转方向。

## 6. 受力旋转模型

### 6.1 冲量记录

发射球真正接触泡泡簇时立即记录：

```text
impactPointWorld
incomingDirectionWorld
collidedCell
attachmentCell
shotSequence
```

记录必须发生在同色消除和特殊效果修改棋盘之前。即使发射球随后形成匹配并消失，本次碰撞产生的冲量仍然有效。

### 6.2 力矩

设：

```text
r = impactPointWorld - trappedSpriteWorldCenter
J = normalize(incomingDirectionWorld) × projectileImpulse
```

二维力矩为：

```text
torque = r.x × J.y - r.y × J.x
```

若屏幕坐标系约定逆时针为正：

- `torque > 0`：逆时针旋转。
- `torque < 0`：顺时针旋转。
- `torque ≈ 0`：几乎不旋转。

该公式同时包含距离和角度影响：

```text
|torque| = |r| × |J| × |sin(α)|
```

其中 `α` 是半径方向与入射方向的夹角。

结果：

- 正对被困精灵中心发射时，切向分量接近零，旋转很小。
- 命中外圈时，力臂更长，旋转更明显。
- 擦着泡泡簇边缘发射时，切向分量最大。
- 左右对称入射会产生大小相近、方向相反的旋转。

### 6.3 转动惯量

完成消除和支撑扫描后，使用仍受被困精灵支撑的泡泡计算转动惯量：

```text
I = coreInertia + Σ(mass_i × distance_i²)
```

首版所有允许进入被困精灵模式的泡泡使用相同质量。暂不为颜色球、冰球和石球建立不同质量，避免玩法规则难以理解。

`coreInertia` 用于：

- 防止剩余泡泡很少时角速度过大。
- 表达中心被困精灵和旋转连接结构的基础惯量。
- 让末盘旋转仍然可控。

初始角速度：

```text
ω0 = clamp(torqueScale × torque / I, -maxAngularSpeed, maxAngularSpeed)
```

### 6.4 阻尼

旋转使用指数衰减：

```text
ω(t) = ω0 × e^(-damping × t)
θ(t) = θ0 + ω0 / damping × (1 - e^(-damping × t))
```

优点：

- 不同设备帧率下的最终角度一致。
- 转动开始快、停止自然。
- 不依赖逐帧累加得到最终结果。
- 暂停和恢复时可以从明确状态继续。

当满足任一条件时停止：

- `|ω| <= stopAngularSpeed`。
- 达到 `maxDurationSec`。
- 本次累计转角达到 `maxStepAngleDeg`。
- 棋盘已完全清空。

停止时只把角速度归零，保留当前任意角度，不吸附到 60° 倍数。

### 6.5 推荐首轮参数

| 参数 | 推荐初值 | 说明 |
| --- | ---: | --- |
| `projectileImpulse` | 1 | 固定发射速度下使用归一化冲量 |
| `torqueScale` | 1 | 全局旋转力度 |
| `coreInertia` | 8 | 约等于8个普通泡泡质量单位 |
| `maxAngularSpeedDeg` | 110 | 最大角速度 |
| `angularDamping` | 5 | 指数阻尼 |
| `stopAngularSpeedDeg` | 2 | 停止阈值 |
| `maxStepAngleDeg` | 45 | 单次最大累计转角 |
| `maxDurationSec` | 0.9 | 单次最长旋转时间 |
| `tangentialDeadZone` | 0.05 | 过滤几乎径向的浮点抖动 |

上述值是首轮调试起点。正式数值应通过径向、斜向、切向、内圈和外圈五组实机样本调整。

## 7. 单次发射结算流程

```text
aiming
  → projectile_flying
  → impact_captured
  → attachment_committed
  → match_and_special_resolution
  → trapped_sprite_support_scan
  → floating_drop_registration
  → trapped_sprite_cluster_rotation
  → outcome_resolution
  → aiming
```

详细顺序：

1. 玩家完成瞄准并发射。
2. 发射球按左墙、右墙和顶部边界反弹规则飞行；未命中时只有低于炮台位置才消失。
3. 命中泡泡簇时记录碰撞点、最终入射方向和待计算冲量。
4. 将接触点转换到被困精灵局部坐标，原子提交吸附格。
5. 执行同色匹配、解冻、爆炸、钥匙等当前允许的结构变化。
6. 所有同步结构变化完成后，从被困精灵邻接格执行支撑搜索。
7. 移除无支撑泡泡，并在当前周期注册正常掉落。
8. 使用剩余受支撑泡泡计算惯量和初始角速度。
9. 受支撑泡泡簇围绕被困精灵旋转；掉落泡泡不再跟随旋转层。
10. 旋转、掉落和延迟效果全部稳定后判断获救、球数耗尽或恢复瞄准。

### 7.1 无匹配发射

即使没有形成同色匹配，也要完成以下步骤：

- 提交吸附。
- 执行被困精灵支撑状态检查。
- 计算本次碰撞产生的旋转。
- 锁定输入直到旋转结束。

### 7.2 发射球被消除

发射球吸附后立即形成匹配并被移除时：

- 使用碰撞前记录的冲量。
- 使用消除后的受支撑泡泡集合计算惯量。
- 如果仍有泡泡，则继续旋转。
- 如果棋盘已经清空，则跳过空旋转并进入获救流程。

### 7.3 延迟特殊效果

如果特殊效果会在延迟后继续修改棋盘结构：

- 彩虹同化、爆破移除、冰块融化等即时结构变化先完成，并用变化后的受支撑集合计算碰撞旋转。
- 漩涡轮换和藤蔓预告属于后续拓扑阶段；整盘碰撞旋转开始后先保存当前结算，待整盘旋转完全停止再依次执行漩涡、藤蔓及最终支撑扫描。
- 漩涡动画的起点、终点及爆破/融冰特效坐标必须通过当前被困精灵角度转换为世界坐标。
- 禁止在正式旋转过程中并行修改格子拓扑。

## 8. 掉落规则

### 8.1 当前周期立即掉落

删除桥接泡泡后产生的无支撑分支，必须在本次发射结算中完成：

```text
findFloatingCells
  → removeFloatingCells
  → registerDrops
```

禁止出现棋盘状态已经无支撑，但渲染仍保留到下一次发射的情况。

### 8.2 脱离权威棋盘

泡泡进入掉落系统时：

1. 读取脱离瞬间的世界坐标。
2. 从棋盘格数据中移除。
3. 以世界坐标放入掉落层。
4. 后续只由 `FallingMarbleSystem` 驱动。

当前实现没有旋转父节点；掉落注册时复制脱离瞬间的世界坐标，后续不会再读取棋盘旋转角。

### 8.3 切向初速度

切向初速度属于后续表现增强，首版仍使用统一掉落初速度。未来接入时使用：

```text
Vtangent.x = -angularVelocity × radiusVector.y
Vtangent.y =  angularVelocity × radiusVector.x
Vinitial = Vtangent × tangentVelocityScale
```

随后再由正常重力、精灵碰撞和罐子收集系统处理。

接入该增强时，`tangentVelocityScale` 必须成为显式配置并补齐专项验证；当前配置合同中不存在该字段。

## 9. 棋盘边界与安全区域

### 9.1 禁用普通棋盘推进

被困精灵模式明确禁用：

- 顶部行支撑。
- 顶部可吸附边界。
- 顶部空槽全盘崩塌。
- `BoardViewportSystem` 的行推进和可见行调整。
- `reach_danger_line` 失败条件。
- 依赖 `dropInterval` 的普通棋盘下移。
- 依赖 `initialDropSpaceRows` 的开局和复活空间恢复。

这些字段不应保留一个无意义数值来满足旧校验，应改为被困精灵模式专用配置合同。

### 9.2 旋转包围圆（正式关卡投放前补齐）

被困精灵位置和泡泡最大局部半径在关卡加载时执行严格验证：

```text
requiredRadius = max(distance(trappedSprite, occupiedCell)) + bubbleRadius
safeRadius = min(
  trappedSprite到左墙距离,
  trappedSprite到右墙距离,
  trappedSprite到顶部反弹边界距离,
  trappedSprite到炮台禁区距离
)

requiredRadius <= safeRadius
```

旋转不会改变包围圆，因此配置通过后，泡泡簇在任意角度都不会进入墙外或炮台区域。

超出安全半径的关卡必须加载失败，禁止运行时缩放棋盘或把被困精灵位置自动改到其他位置。

## 10. 胜负与目标

### 10.1 胜利目标

新增主目标：

```json
{
  "type": "clear_all",
  "value": 1
}
```

获救条件：

- 棋盘已没有受支撑泡泡。
- 无支撑泡泡已经全部从棋盘移除并注册掉落。
- 没有待执行的结构变化。
- 没有待执行的旋转。
- 被困精灵尚未触发过获救。

支撑扫描确认棋盘已无受困泡泡时，立即且只发出一次 `trapped_sprite_rescued`，不等待已经进入掉落系统的泡泡落入缸内；此时立即播放 `sound/cute_laughter`，被困精灵同时向屏幕上方加速飞行并在完整出屏后隐藏。玩法状态仍进入 `won_pending`，掉落计分、星级确认和最终胜利结算继续等待全部掉落完成，两条时序互不阻塞。

### 10.2 最后连接点

如果最后一个直接连接被困精灵的泡泡被消除：

- 所有外围分支立即失去支撑。
- 所有外围分支在当前周期一起进入掉落系统。
- 不再启动没有受支撑对象的旋转。
- 掉落表现完成后触发被困精灵获救。

### 10.3 失败

首版使用 `shot_limited`：

- 剩余发射数为0时，不立即抢占当前结算。
- 必须等待本次消除、掉落、延迟效果和旋转完成。
- 如果结算后被困精灵已经获救，则胜利优先。
- 如果仍有受支撑泡泡，则进入球数耗尽流程。

被困精灵模式不使用危险线失败。

## 11. 表现设计

### 11.1 渲染层级

逻辑层级：

```text
GameView
  boardLayer
    trappedSpriteNode
    boardBubbleNodes
  projectileRoot
  fallingMarbleRoot
```

规则：

- `trappedSpriteNode` 固定在中心，不挂在旋转节点下。
- 当前实现不额外旋转一个 Cocos 父节点；`boardBubbleNodes` 分别读取权威世界坐标，避免渲染节点成为物理状态源。
- `projectileRoot` 使用世界坐标，不随棋盘旋转。
- `fallingMarbleRoot` 使用世界坐标，不随棋盘旋转。
- 碎裂、爆炸和消除特效必须使用事件发生时的世界坐标。

### 11.2 被困精灵反应

被困精灵作为固定支点，不参与持续旋转，但可以播放轻量受力反馈：

- 命中瞬间朝受力反方向偏移2至4像素。
- 根据力矩方向轻微反向倾斜，最大3°。
- 强冲量时播放惊讶、眨眼或抓紧动作。
- 泡泡全部清空后播放释放、舒展和庆祝动画。

被困精灵反馈只能是表现，不改变逻辑旋转中心。

### 11.3 旋转反馈

- 命中瞬间播放80至120毫秒的泡泡簇压缩或轻震。
- 如果本次吸附产生的力矩实际启动整盘旋转，则不播放命中泡泡周围邻居球的局部反弹，避免局部位移和整盘旋转同时争夺节点位置；只有未启动旋转的吸附才保留邻居反弹。
- 正式旋转使用物理阻尼曲线，不使用固定时长匀速旋转。
- 旋转强度越大，碰撞音效和支点拉伸效果越明显。
- 音效按轻、中、重三档选择，不需要连续修改音调。
- 掉落分支继承切向速度，强化“被甩出”的感觉。

### 11.4 瞄准受力提示

轨迹预测确定碰撞点后，在被困精灵外围显示弧形箭头：

| 强度 | 表现 |
| --- | --- |
| 轻 | 短蓝色弧线 |
| 中 | 黄色中长度弧线 |
| 重 | 红色长弧线 |

箭头方向表示顺时针或逆时针。几乎径向入射时不显示箭头。

提示只显示预测结果，不参与真实冲量计算。

### 12.3 严格校验

`trapped_sprite_rescue` 关卡必须满足：

- `trappedSpriteRescue` 显式存在且为对象。
- `spiritId` 必须属于精灵大厅七名角色 ID，地图和局内资源路径均由该 ID 严格派生，配置不得另写资源路径。
- `anchorCell.row/col` 为有效蜂窝格。
- 被困精灵格在 `layout` 中必须为 `.`。
- 被困精灵格不能存在 `specialEntities`。
- `worldCenter.x/y` 为有限数值。
- `rotation` 所有字段显式存在并在合法范围内。
- 正式关卡与测试关均使用唯一 `clear_all` 主目标。
- `clear_all.value` 必须为1。
- 初始至少有一个泡泡直接邻接被困精灵。
- 初始全部棋盘泡泡必须能连通到被困精灵。
- 顶部行可以为空，不执行顶部锚点校验。
- 不配置普通棋盘的 `dropInterval` 和 `initialDropSpaceRows`，运行时禁用普通棋盘推进、危险线和顶部支撑。
- 首版不允许配置多个被困精灵。
- 只允许彩虹球、爆破球、石球、冰块、漩涡和藤蔓魔灵六类特殊实体。
- 顶部行必须为空，且不参与普通关卡的顶部连续同色校验。
- 救援关不使用普通矩形棋盘70%占位率；正式关必须占满中心之外六角距离1至5的90个槽位，外围不得额外占格。
- `specialEntities` 不得占用顶部行或中心保留格；燃烧瓶、分裂球、虫洞、锁定球和钥匙球仍不兼容。动态遮挡必须为 `none`，局内广告道具列表必须为空。

普通关卡不得出现 `trappedSpriteRescue` 字段。字段与关卡类型不一致时直接报错。

### 12.4 Schema与远程包

首版本地测试关与正式主线生成已同步：

- `LevelConfigLoader`
- `LevelBoardSupportValidator`
- 玩法生成包
- `LevelPackCompactCodec`
- `campaign-level-generation-config`
- 全量远程关卡包与 manifest

正式主线救援关由 `tools/campaign-level-generation-config.js` 集中排期。`npm run redesign:trapped-rescue` 只重写50个救援关对应的表格行与远程包条目，并同步相关 manifest 摘要，保留全部非救援关数据。批量生成策略会自动投放本节列出的六类兼容特殊实体，并按章内五个节拍形成“纯救援、漩涡、藤蔓、双玩法、阶段考核”的递进；计时关、虫洞和动态遮挡仍保持互斥。任何排期冲突、正六边形缺格或越界、同色连通块超过5、中心邻圈连续同色超过2、中心支撑断裂或压缩包字段丢失都必须在生成或校验阶段直接报错。

禁止只修改输出 JSON，也禁止在解码器中把缺失被困精灵配置补成默认值。

### 12.5 救援解锁与存档规则

- `AssistSpiritRescueConfig` 是50个正式救援关到七名精灵身份的运行时权威映射，关卡生成器复用同一配置，禁止生成与结算分别维护两份排期。
- 新档使用 `AssistSpiritStore` v2：只有默认递球手 `milu` 已拥有并出战，其余六名角色保留完整存档项但 `owned=false`。
- 普通主线救援关记录胜利后，必须校验关卡内 `trappedSpriteRescue.spiritId` 与排期映射一致，再幂等写入对应角色 `owned=true`；重复通关不得重复发放或改变既有养成数据。
- 隐藏测试入口运行不记录玩家关卡完成状态，也不解锁角色。
- v1 旧档显式迁移为 v2：保留每名角色的等级、星级和碎片，出战角色重置为 `milu`，再按 `LevelProgressStore.completedLevels` 已完成的正式救援关补齐拥有状态。云档覆盖本地后执行同一补齐流程。
- `equippedSpiritId` 必须指向已拥有角色；未拥有角色的升级状态转换返回 `NOT_OWNED`，底层直接出战调用保持 Fail-Fast。
- 精灵大厅只将未拥有角色的列表头像代理切换为内置 `2d-gray-sprite` 材质，解锁头像恢复 `2d-sprite`；操作按钮保持可点击，以便升级、出战统一提示“该精灵尚未解锁，请先完成对应救援关卡”。

## 14. 运行时系统边界

### 14.1 `TrappedSpriteRescueSystem`

新增独立系统负责：

- 加载并验证被困精灵模式运行参数。
- 保存旋转角度和当前旋转阶段。
- 记录本次碰撞冲量。
- 根据当前受支撑泡泡计算转动惯量。
- 计算初始角速度、停止时间和最终角度。
- 提供局部坐标与世界坐标转换。
- 生成旋转快照和一次性事件。
- 在暂停、恢复、重开和销毁时维护完整状态。

该系统不负责：

- 同色匹配。
- 支撑搜索。
- 删除棋盘泡泡。
- 掉落物理。
- Cocos 节点动画。

### 14.2 `SupportSystem`

支撑系统增加显式策略：

```text
top_anchor
trapped_sprite_anchor
```

普通模式继续使用顶部、锁定球和虫洞规则。被困精灵模式只使用被困精灵邻接格。

禁止通过“先按普通模式扫描，再额外保留被困精灵附近泡泡”的叠加方式实现，否则会留下多个支撑来源。

### 14.3 `BubbleGrid`

需要增加：

- 被困精灵保留格检查。
- 当前旋转角下的格子世界坐标。
- 世界坐标到被困精灵局部坐标的转换。
- 旋转棋盘的射线碰撞。
- 被困精灵模式专用吸附候选筛选。
- 禁止顶部吸附。

格子拓扑、颜色、特殊字段和邻接算法继续保持局部六边形权威。

### 14.4 `TrajectoryPredictor`

被困精灵模式预测：

- 不计算 `topAttachY`。
- 只检测左右墙、泡泡簇和顶部射失边界。
- 使用旋转后的格子世界坐标。
- 输出实际碰撞前的最终方向。
- 输出吸附格和吸附中心。
- 输出最终入射方向；力矩由真实落位后的权威结算计算。

### 14.5 `GameManager`

`GameManager`负责把当前发射结算串成单一事务：

```text
记录冲量
→ 吸附
→ 同步结构变化
→ 被困精灵支撑扫描
→ 掉落注册
→ 启动旋转
→ 等待稳定
→ 胜负判断
```

不能由渲染回调决定何时扫描支撑或开放下一次发射。

### 14.6 `BoardViewportSystem`

被困精灵模式下必须进入显式禁用状态。若被困精灵模式调用以下能力应直接报错：

- 行推进。
- 最小可见行调整。
- 顶部空槽崩塌。
- 危险线判定。
- 复活空间上移。

## 17. 边界情况

### 17.1 只剩一个直接支撑泡泡

命中该泡泡但未消除：

- 正常吸附。
- 新泡泡与原泡泡共同受支撑。
- 根据两颗泡泡的新惯量旋转。

消除该泡泡：

- 外围全部失去支撑。
- 本次结算立即掉落。
- 无受支撑泡泡时进入获救。

### 17.2 命中后整盘清空

- 保留碰撞得分和消除结果。
- 不启动旋转。
- 不创建空的旋转动画。
- 等待掉落和消除表现完成后获救。

### 17.3 射失

- 消耗发射数。
- 不新增泡泡。
- 不产生旋转。
- 不调用顶部吸附。
- 仍按完整发射周期判断球数耗尽。

### 17.4 暂停和恢复

暂停时冻结：

- 旋转物理时间。
- 掉落物理。
- 延迟特殊效果。
- 输入状态。

恢复后从保存的旋转起始角、已用时间和目标状态继续，禁止按现实经过时间直接跳到结束。

### 17.5 重开和退出

- 清空待处理冲量。
- 清空旋转事件。
- 销毁旋转泡泡节点。
- 解除掉落节点与旋转层关系。
- 清理被困精灵 prefab 和短期资源引用。

## 18. 验收标准

### 18.1 配置

1. 顶部行完全为空的被困精灵关卡可以通过校验。
2. 相同布局放在普通模式下因缺少顶部锚点而报错。
3. 被困精灵格放置泡泡时直接报错。
4. 被困精灵格放置特殊实体时直接报错。
5. 初始存在不连通被困精灵的泡泡时直接报错。
6. 缺失任意必填旋转参数时直接报错。
7. 旋转包围圆越界时直接报错。
8. 被困精灵模式配置燃烧瓶、分裂球、虫洞、锁定球或钥匙球时直接报错。
9. 彩虹球、爆破球、石球、冰块、漩涡和藤蔓魔灵可同时通过配置与初始支撑校验。

### 18.2 支撑

1. 被困精灵六个邻接格是唯一支撑种子。
2. 顶部行泡泡不会因为位于第0行而获得支撑。
3. 删除单个桥接泡泡后，整个外围分支本次结算立即掉落。
4. 删除最后一个被困精灵邻接泡泡后，所有外围泡泡一起掉落。
5. 无支撑泡泡不会残留到下一次发射。

### 18.3 旋转

1. 正对被困精灵中心发射，旋转接近零。
2. 左右对称切向发射产生大小相近、方向相反的旋转。
3. 相同入射角下，外圈命中比内圈命中产生更大力矩。
4. 泡泡数量越多、分布越远，角速度越低。
5. 角速度和单次转角不会超过配置上限。
6. 棋盘停在任意角度，不会吸附到60°倍数。
7. 暂停和恢复不会改变最终角度。
8. 不同帧率下的最终角度保持一致。

### 18.4 碰撞与吸附

1. 任意旋转角下，预测碰撞泡泡与真实碰撞泡泡一致。
2. 任意旋转角下，预测吸附格与真实吸附格一致。
3. 左右墙或顶部反弹后，使用最终入射方向计算力矩。
4. 顶部碰撞必须反弹且不会产生顶部吸附；只有球心低于炮台位置才允许射失消失。
5. 运行时找不到预测吸附格时直接暴露错误。
6. 被困精灵保留格永远不能吸附泡泡。

### 18.5 掉落与表现

1. 掉落泡泡从旋转层脱离后不再跟随泡泡簇。
2. 掉落泡泡起点与脱离瞬间的世界坐标一致。
3. 掉落起点使用脱离瞬间的旋转后世界坐标；切向掉落速度留待表现增强。
4. 泡泡簇旋转期间不能再次发射。
5. 整盘清空后不播放空旋转。
6. 被困精灵节点不随泡泡簇持续旋转。

### 18.6 胜负

1. 最后一组泡泡清除后进入被困精灵获救流程。
2. 最后一个发射球完成获救时判定胜利，不进入球数耗尽。
3. 最后一个发射球未完成获救时，等旋转和掉落结束后进入球数耗尽。
4. 被困精灵模式不会触发危险线失败。
5. 清屏胜利只结算一次。
6. 获救成功只播放一次 `cute_laughter`，旋转等待帧、胜利延迟和重复渲染不能重复播放。
7. 获救飞离动画只启动一次，飞行期间刷新不能把精灵重置到中心，节点必须完整越过屏幕上边界后隐藏。

## 22. 设计结论

该玩法的关键不是“让棋盘节点转起来”，而是建立一套完整的被困精灵锚点棋盘规则：

1. 被困精灵是唯一支撑源。
2. 六边形格子拓扑保持不变。
3. 整个受支撑泡泡簇共享权威旋转角度。
4. 碰撞和吸附在旋转坐标系中保持严格一致。
5. 旋转强度由真实入射方向、命中距离和当前惯量共同决定。
6. 结构变化后立即重算被困精灵支撑并完成同周期掉落。
7. 顶部支撑、棋盘推进、危险线和额外锚点在该模式中明确禁用。

当前首版已经完成配置、玩法状态、坐标变换、支撑、掉落、基础渲染、测试入口和玩法生成包闭环；编辑器与远程关卡生成链路需在正式主线投放前完成。
