# 棋盘遮挡玩法设计

## 1. 文档状态

- 状态：已实现并作为当前玩法与配置合同
- 适用项目：Bubble 泡泡龙主线关卡与特殊浮岛限时关
- 目标机制：在棋盘泡泡区域加入云朵、树叶等前景遮挡；每次开局确定性生成不同位置，并通过道具或与关卡模式一致的倒计时清除
- 本文档定义当前已实现的玩法、配置、运行时边界、表现规则和验收标准

## 2. 设计目标

### 2.1 核心目标

1. 遮挡一部分棋盘信息，提高颜色判断、路线规划和发射决策难度。
2. 允许玩家使用局内道具主动清理遮挡，形成明确的道具消费场景。
3. 支持按完成发射次数或真实时间自动消散，避免所有关卡都依赖道具。
4. 保证遮挡仅影响视觉，不改变泡泡碰撞、连接、消除、掉落和胜负权威。
5. 保持关卡配置可生成、可验证、可压缩、可导入编辑器。
6. 同一关卡连续两次开局选择不同遮挡位置，同时保留种子以支持问题复现。

### 2.2 非目标

首版不包含以下行为：

- 遮挡物不占用棋盘格。
- 遮挡物不阻挡发射球。
- 遮挡物不参与颜色匹配。
- 遮挡物不提供支撑，也不会导致泡泡悬空。
- 普通消除、爆炸和掉落不会顺带清除遮挡物。
- 不根据缺失配置自动生成默认遮挡。
- 不兼容读取未迁移的旧遮挡配置。

## 3. 核心玩法规则

每个遮挡区覆盖一组相邻蜂窝格。遮挡区下方的泡泡仍然存在，并按正常规则参与全部玩法计算。

玩家可以向遮挡区正常瞄准和发射。轨迹预测、碰撞落点、匹配消除、悬空掉落、特殊泡泡触发和危险线判定全部使用真实棋盘状态，不读取遮挡表现状态。

关卡配置不只保存一个固定遮挡位置，而是保存多个经过完整校验的位置变体。每次开始一次新的关卡尝试时，根据本次尝试种子选择一个变体，并保证与本关上一次使用的变体不同。遮挡位置在本次尝试开始后固定，暂停、切后台、弹窗恢复和局内棋盘变化都不得重新随机。

遮挡区可以通过以下方式清除：

| 规则 | 含义 | 推荐使用位置 |
| --- | --- | --- |
| `item_or_shots` | 使用道具，或完成指定次数的发射后消散 | 普通限步关 |
| `item_or_seconds` | 使用道具，或经过指定秒数后消散 | 90秒无限球关 |

无论配置了哪种清理规则，只要某个遮挡区覆盖坐标中的泡泡已经全部被匹配、爆炸、道具或悬空掉落移除，该遮挡区立即消失，不再继续等待秒数、发射次数或清障道具。多个遮挡区分别判断，空区域消失不会影响仍覆盖泡泡的其他区域。

清理规则由关卡模式唯一决定：普通`shot_limited`关卡的所有遮挡区必须使用`item_or_shots`；特殊浮岛`timed_infinite_shots`限时关的所有遮挡区必须使用`item_or_seconds`。普通关禁止配置真实秒数倒计时，限时关禁止配置发射次数倒计时，加载到不匹配配置时直接报错。

使用`item_or_seconds`规则时，`assets/game/image/props/clock.png`按58×60原图尺寸显示在遮挡物正中心，不再缩小；剩余秒数放在钟表下半部分的黑色圆角框内，并位于钟表Sprite之上。发射次数和仅道具清理提示不显示钟表图标。

## 4. 遮挡类型

### 4.1 云朵

- 配置值：`cloud`
- 视觉资源：`assets/game/image/props/cloud.png`。
- 视觉特征：半透明云团进行缓慢、轻微的透明度呼吸，单段2.4秒、完整周期4.8秒；透明度仅在236至252之间变化，初始透明度为244，避免呼吸时遮挡过淡。
- 信息遮挡：隐藏泡泡颜色和内部细节，但保留轻微圆形轮廓。
- 推荐覆盖范围：单区5至10格。
- 清理表现：从中心向外吹散，建议持续0.45秒。
- 倒计时提示：剩余发射次数固定显示在云团正中并位于云团Sprite之上；剩余秒数显示在正中钟表底部框内。

### 4.2 树叶

- 配置值：`leaves`
- 视觉资源：`assets/game/image/props/leaves.png`。
- 视觉特征：树叶与细枝形成较实的静态前景遮挡，叶片间保留少量缝隙；不播放旋转或摆动动作。
- 信息遮挡：遮挡程度高于云朵，但仍应让玩家辨认被覆盖区域存在泡泡。
- 推荐覆盖范围：单区4至8格。
- 清理表现：树叶向左右或斜上方吹飞，建议持续0.5秒。
- 倒计时提示：剩余发射次数固定显示在树叶区视觉中心并位于树叶Sprite之上；剩余秒数显示在正中钟表底部框内。

云朵和树叶仅有视觉差异，共用相同规则和运行时系统，不建立两套玩法逻辑。

## 5. 清障道具

### 5.1 道具定义

- 道具ID：`snow_removal`
- 显示名称：除雪剂（本功能复用现有库存、广告补给和持久背包链路）
- 使用效果：存在棋盘遮挡时优先清除本局全部遮挡区；没有遮挡时保持原有除雪效果。
- 使用范围：云朵和树叶。
- 是否消耗发射球：否。
- 是否推进遮挡发射次数倒计时：否。

### 5.2 操作流程

1. 玩家点击底部“除雪剂”。
2. `GameManager.previewSnowRemoval()`先检查局内库存与当前可用状态。
3. 若存在棋盘遮挡，预览目标为当前全部活动遮挡区；否则继续走原有冰块目标。
4. 表现动画完成后，`GameManager.useSnowRemoval()`再次核对目标集合。
5. 核对成功后原子提交遮挡清理并消耗一份局内道具库存。
6. 返回`accepted: true`后，Bootstrap层再扣除一份持久背包库存。
7. 失败或目标变化时直接报错，不扣持久库存。

### 5.3 消费规则

只有以下条件全部满足时才能消耗道具：

- 游戏处于`running`状态。
- 当前没有飞行中的发射球。
- 当前没有棋盘下移、漩涡、虫洞、藤蔓施法等阻塞阶段。
- 没有其他互斥的道具选取状态。
- 目标遮挡区存在且状态为`active`。
- 局内除雪剂数量大于0，或允许通过现有广告补给链获取。

点击道具、进入选取状态、取消选取、点击空白处、点击已经消散的区域、库存不足或状态繁忙时都不得扣除库存。

自动消散和玩家点击在同一帧发生时，以`BoardOcclusionSystem`的原子状态修改结果为准。一个遮挡区只能产生一次清理结果，不能重复消耗道具。

## 6. 关卡配置

### 6.1 配置位置

遮挡物是多格、非碰撞的表现区域，不应放入占用单格的`level.specialEntities`。关卡增加独立的动态选位计划。配置保存多个完整的位置变体，运行时只选择其中一个，不能临时随机拼接未经校验的区域：

```json
{
  "level": {
    "boardOcclusionPlan": {
      "generatorVersion": 1,
      "mode": "per_attempt_no_repeat",
      "variants": [
        {
          "id": "variant_1",
          "zones": [
            {
              "id": "zone_1",
              "visualType": "cloud",
              "cells": [
                {"row": 4, "col": 2},
                {"row": 4, "col": 3},
                {"row": 5, "col": 2},
                {"row": 5, "col": 3}
              ],
              "clearRule": {
                "kind": "item_or_shots",
                "shots": 5
              }
            }
          ]
        },
        {
          "id": "variant_2",
          "zones": [
            {
              "id": "zone_1",
              "visualType": "leaves",
              "cells": [
                {"row": 6, "col": 6},
                {"row": 6, "col": 7},
                {"row": 7, "col": 6},
                {"row": 7, "col": 7}
              ],
              "clearRule": {
                "kind": "item_or_shots",
                "shots": 5
              }
            }
          ]
        }
      ]
    }
  }
}
```

没有遮挡玩法的关卡也必须显式配置：

```json
{
  "boardOcclusionPlan": {
    "generatorVersion": 1,
    "mode": "none",
    "variants": []
  }
}
```

### 6.2 严格校验

`boardOcclusionPlan`必须显式存在并且是对象，禁止字段缺失后补成默认关闭状态。

选位计划必须满足：

- `mode`只能是`none`、`per_attempt_no_repeat`或`per_run`。
- `generatorVersion`必须是受支持的正整数。
- `none`必须配置空`variants`。
- `per_attempt_no_repeat`至少包含2个变体，正式关卡建议至少4个。
- `per_run`至少包含1个变体；同一个挑战Run重试时保持相同遮挡位置。
- 每个变体必须有唯一的非空`id`。
- 生成器必须保证不同变体的遮挡区数量和覆盖格数一致，`visualType`允许在`cloud`和`leaves`之间轮换。
- 任意两个变体不能拥有完全相同的格子集合。
- 正式关卡任意两个变体的覆盖格重叠比例不得超过50%，避免玩家感知不到位置变化。

每个变体中的遮挡区必须独立满足：

- `id`为非空字符串且关卡内唯一。
- `visualType`只能是`cloud`或`leaves`。
- `cells`必须包含3至7个`{row, col}`坐标。
- 坐标必须是合法的`odd-r-hex`棋盘格。
- 区域内所有格子必须按六方向蜂窝邻接保持连通。
- 同一区域不能包含重复坐标。
- 同一关卡的不同遮挡区不能重叠。
- 初始覆盖坐标必须对应普通彩色泡泡。
- 首版禁止覆盖特殊泡泡、障碍球、钥匙、锁、技能球、虫洞、漩涡和藤蔓魔灵。

清理规则必须满足：

- `item_or_shots`必须配置`kind`和正整数`shots`，禁止配置`seconds`。
- `item_or_seconds`必须配置`kind`和正整数`seconds`，禁止配置`shots`。
- `shot_limited`只能使用`item_or_shots`，`timed_infinite_shots`只能使用`item_or_seconds`。
- 道具清理由现有`snow_removal`行为统一接入，不在每个区域重复配置`itemId`。

### 6.3 开局选位规则

主线关使用`per_attempt_no_repeat`。Bootstrap在每次真正开始关卡尝试时生成非空`seed`、正整数`attemptIndex`和`runMode`，作为Start Context传给`GameManager.startLevel`。不能在`LevelRenderer`中生成随机数，也不能由逻辑层和表现层分别选位。

选择过程必须是确定性的：

1. 读取`LevelAttemptStatsStore.attemptCountByLevel[levelId]`并计算即将开始的`attemptIndex`。
2. 使用`levelId + generatorVersion`计算该关固定起始偏移。
3. 使用`(baseOffset + attemptIndex - 1) % variantCount`直接得到变体索引。
4. 成功选出后把`variantId`和本次种子写入`BoardOcclusionSystem`运行时状态。
5. 本次尝试结束前，遮挡位置不得再次变化。

该算法不重抽、不依赖额外历史字段，至少两个变体时天然保证连续两次不同；当前正式关卡使用4个变体循环。

“每次开局不同”的准确合同是“连续两次关卡尝试不使用同一个变体”。有限棋盘不可能永久保持全局不重复，全部变体使用过后允许再次出现。

遮挡直接复用现有严格持久化的关卡尝试次数，不新增重复状态字段。退出选关或关闭游戏后再次进入仍会得到下一个变体。

随机挑战保持两类种子：

- `challengeSeed`决定挑战棋盘、颜色和目标。
- `challengeSeed`同时作为`per_run`遮挡选择种子。

随机挑战默认使用`per_run`：同一Run重试时复用相同遮挡位置，下一Run才重新选择。如果产品明确要求随机挑战每次重试也改变遮挡，可将该关配置为`per_attempt_no_repeat`，但不得改变`challengeSeed`。

### 6.4 Schema与远程包

遮挡字段作为关卡Schema v1中的新增必填字段，全部1000关已经重新生成，不保留缺字段的旧配置。`LevelPackCompactCodec`对完整`level`对象做克隆，只压缩`specialEntities`，因此遮挡计划能无损往返，不需要新增压缩码表。实施同步修改：

- `LevelConfigLoader`
- `LevelPackCompactCodec`
- 本地关卡生成规则
- 远程关卡生成规则
- 位置变体生成器与确定性种子算法
- 关卡内容校验器
- 关卡编辑器导入和导出
- `LevelAttemptStatsStore`及玩家档案显式迁移
- 本地1至10关
- 远程11至1000关包
- 远程manifest的字节数与SHA-256

禁止只修改个别输出JSON，也禁止在加载器中为旧配置添加默认值或兼容分支。

## 7. 运行时系统

### 7.1 系统边界

新增独立的`BoardOcclusionSystem`。遮挡状态不写入`BubbleGrid`，避免视觉机制污染棋盘碰撞和支撑权威。

`BoardOcclusionSystem`由`GameManager`创建和驱动，负责：

- 校验Start Context中的`seed`、`attemptIndex`和`runMode`。
- 从关卡位置变体中确定性选择本次遮挡布局。
- 校验选择结果与`selectedVariantId`一致。
- 使用解析后的遮挡区初始化本次局内状态。
- 推进发射次数倒计时。
- 推进秒数倒计时。
- 校验玩家道具目标。
- 原子提交道具清理或自动消散。
- 生成轻量运行时快照。
- 生成一次性清理事件。

### 7.2 运行时状态

每个遮挡区保存：

```text
id
visualType
cells
status: active | cleared
remainingShots
remainingTimeMs
clearReason: item | shots_elapsed | time_elapsed | level_end
```

系统级状态额外保存：

```text
attemptSeed
selectedVariantId
generatorVersion
activeZones
version
```

`activeZones`是本次尝试唯一权威的遮挡位置。清理、渲染和事件必须读取同一份解析结果，禁止任何模块重新随机。

系统额外保存单调递增的`version`。只有状态或倒计时显示桶发生变化时才提高对应渲染版本，避免每帧全量重绘。

### 7.3 Runtime Snapshot

在运行时快照中增加：

```text
systems.boardOcclusionSystem.version
systems.boardOcclusionSystem.mode
systems.boardOcclusionSystem.selectionSeed
systems.boardOcclusionSystem.variantId
systems.boardOcclusionSystem.activeZones
```

遮挡快照不进入`board.cells`，也不改变`board.version`。

## 8. 倒计时规则

### 8.1 发射次数

发射次数不能在玩家按下发射或`shotsFired`增加时扣减，必须在一次完整发射周期结算完毕后统一推进。

完整发射周期包括：

1. 发射球飞行并确定落点。
2. 匹配、爆炸、解冻和特殊球效果完成。
3. 悬空球进入掉落链路。
4. 漩涡旋转完成。
5. 虫洞位移完成。
6. 藤蔓魔灵预告与施法完成。
7. 棋盘结构稳定，即将重新开放输入。

一次完整周期只减少一次`remainingShots`。道具使用、广告补给、开局倒计时、暂停、重开和退出都不减少次数。

当数值从1变为0时，系统立即提交清理，生成`shots_elapsed`事件，然后再开放下一次输入。

### 8.2 秒数

秒数由`GameManager.update(dt)`推进。

- 仅在关卡处于`running`状态时推进。
- 游戏暂停时停止。
- 开局倒计时和首次玩法说明期间停止。
- 限时关计时器暂停时同步停止。
- 正常发射球飞行、消除动画和特殊球动画期间继续推进。
- 只在整数秒变化时更新倒计时显示。
- 限时关每秒触发`timer`局部刷新时，必须同步更新遮挡区倒计时Label和遮挡渲染版本键，不得重建云朵/树叶节点或重启呼吸动画。

当时间到0时提交`time_elapsed`清理事件。遮挡消散只修改遮挡系统状态，不修改棋盘，因此允许在发射球飞行期间发生。

## 9. 棋盘与特殊机制交互

### 9.1 棋盘下移

遮挡区绑定关卡格坐标。渲染位置由格坐标、`maxColumns`和当前`viewportOffsetY`计算，因此棋盘整体下移时遮挡区必须同步移动。

### 9.2 漩涡与虫洞

漩涡和虫洞移动底层泡泡，遮挡区域保持在原格坐标。泡泡可以移入或移出遮挡区。

遮挡区不参与漩涡轨道完整性和虫洞内部格移动计算。

### 9.3 藤蔓魔灵

首版不允许初始遮挡藤蔓魔灵。普通泡泡被藤蔓缠绕后可以位于遮挡区下方，但以下关键信息必须显示在遮挡层上方：

- 藤蔓施法预告。
- 目标指示。
- 魔灵受击反馈。
- 藤蔓解除反馈。

### 9.4 爆炸与技能球

彩虹球、爆炸球、燃烧瓶和其他范围效果正常作用于被遮挡泡泡，不要求先揭开区域。

爆炸、碎裂和掉落动画应显示在遮挡层前方，为玩家提供真实结果反馈。

### 9.5 清屏与胜负

遮挡区不计入棋盘剩余泡泡数，也不参与`clear_all`。

棋盘正常清空并达到一星条件后，立即进入现有胜利结算。所有仍然激活的遮挡区以`level_end`原因淡出，不消耗道具，不延迟胜利。

失败、重开或退出关卡时直接销毁本次遮挡表现。`activeZones`、剩余次数和剩余时间不写入跨局状态；下一次位置由已有的关卡累计尝试次数推导。

### 9.6 重开、暂停与恢复

- 普通主线关点击重玩时使用新的`attemptIndex`，并选择与上一次不同的变体。
- 失败后再次开始、退出选关后重新进入，都属于新的关卡尝试。
- 暂停、切后台、关闭说明弹窗和恢复输入不属于新的关卡尝试，必须继续使用当前`selectedVariantId`。
- 同一次尝试中即使渲染层节点被重建，也必须从`BoardOcclusionSystem.activeZones`恢复，禁止重新选位。
- 随机挑战使用`per_run`时，重试复用原`selectedVariantId`；使用`per_attempt_no_repeat`时才重新选择遮挡位置。

## 10. 渲染设计

### 10.1 层级

建议层级如下：

```text
BoardLayer                 40
BoardOcclusionLayer        43
BubbleShatterLayer         44
FallingLayer               45
OcclusionIndicatorLayer    47
HUDLayer                   50
```

效果要求：

- 固定棋盘泡泡位于遮挡物后方。
- 碎裂、爆炸和掉落球位于遮挡物前方。
- 倒计时数字位于遮挡物前方。
- HUD、评论、弹窗和胜负界面完全不受遮挡。

### 10.2 Sprite组织

- 云朵和树叶资源放在`game`分包。
- 同类型遮挡Sprite使用同一图集、材质和blend。
- 遮挡Sprite集中在独立层连续渲染。
- 每格遮挡节点必须池化复用。
- 单关建议最多24个遮挡Sprite。
- 倒计时数字使用BMFont或数字Sprite，避免多个普通Label打断合批。

### 10.3 视觉状态

遮挡区至少包含以下表现状态：

- `active`：正常遮挡与轻微循环动画。
- `warning`：剩余2次发射或2秒时轻微脉冲。
- `clearing`：播放吹散动画，不再接受点击。
- `cleared`：节点回收到对象池。

## 11. 资源与生命周期

玩法资源建议划分：

- `assets/game/image/props/cloud.png`：云朵遮挡。
- `assets/game/image/props/leaves.png`：树叶遮挡。
- `assets/game/image/props/clock.png`：秒数倒计时钟表图标。
- `assets/game/image/props/`：局内底部道具图标。
- `assets/ui/image/props/`：背包、商店和开局道具界面的独立图标副本。

`LevelRenderer`只预加载当前关卡实际使用的遮挡类型。退出局内时释放关卡专属遮挡SpriteFrame、动画和对象池引用，并遵守现有`game`分包释放生命周期。

## 12. 关卡编辑器设计

### 12.1 独立测试关

- 测试配置：`assets/map/config/levels/level_board_occlusion_test.json`。
- 入口：开启选关页隐藏测试模式后，点击同一排动态生成的“遮挡”按钮。
- 每次进入或重开按测试尝试序号轮换4套位置，连续两次不重复。
- 测试关属于普通`shot_limited`关卡，每套位置的云朵和树叶区域都按发射次数消散；云朵为4次，树叶为5次。
- 秒数倒计时通过正式`timed_infinite_shots`限时关及自动化校验验证，不在普通测试关中混用。
- 测试关开局固定发放3个局内除雪剂，用于验证主动清除；测试关使用除雪剂不扣除玩家永久背包库存。

关卡编辑器新增“遮挡计划”和“位置变体”工具：

1. 创建`boardOcclusionPlan`并选择`mode`。
2. 创建第一个位置变体并填写唯一`variantId`。
3. 在变体内选择`cloud`或`leaves`。
4. 在蜂窝格上刷选覆盖区域，相邻格组成一个遮挡区。
5. 遮挡区清理规则由关卡模式锁定；普通关只填写发射次数，限时关只填写秒数。
6. 复制当前变体生成新变体，只调整各遮挡区的`cells`。
7. 编辑器实时显示覆盖范围、区域ID、变体ID和倒计时标记。
8. 支持在变体之间切换、对比重叠比例、追加格、移除格和删除整个变体。
9. 提供“模拟开局”能力时，应输入`seed`和`attemptIndex`并显示确定性选中的变体。
10. 提供“连续尝试预览”，验证相邻两次不会选择相同变体。

复制变体后，遮挡区ID、类型、清理规则和覆盖格数锁定一致；编辑器只允许调整位置。若确需改变规则，必须对全部变体同步修改。

保存时必须执行与运行时加载器相同的严格校验。区域不连通、重叠、覆盖特殊实体、变体规则不一致、变体完全相同、重叠比例超标或动态模式变体数量不足时，直接阻止保存并报告具体变体ID、区域ID和坐标。

## 13. 新手教学

首次出现遮挡玩法时使用现有特殊玩法说明弹窗：

- 文案一：云朵或树叶会遮住泡泡颜色，但不会阻挡发射。
- 文案二：普通关完成指定发射次数后自动消散，限时关等待秒数倒计时结束后自动消散。
- 文案三：使用除雪剂可以立即清除当前遮挡。

所有正式遮挡区都允许通过对应倒计时自动消散，也可以使用除雪剂立即清除，不得形成必须消耗库存才能继续识别棋盘的永久遮挡。

教学弹窗和手势指引期间暂停限时关计时与遮挡秒数倒计时。

## 14. 关卡投放建议

| 关卡区间 | 推荐投放 |
| --- | --- |
| 1至30关 | 不出现遮挡 |
| 31至59关 | 单个云朵或树叶区，4格，4个位置变体，普通关4至6次发射后消散 |
| 60至79关 | 单个云朵或树叶区，5格，4个位置变体，普通关4至6次发射后消散 |
| 80至119关 | 两个云朵/树叶区，每区5格，4个位置变体 |
| 120关以后 | 两个云朵/树叶区，每区6格，4个位置变体 |
| 121至300关 | 最多两个区域，至少6个位置变体，总覆盖不超过初始普通泡泡的20% |
| 301关以后 | 最多两个区域，至少6个位置变体，总覆盖不超过25%，继续严格匹配关卡模式 |
| 90秒特殊关 | 单个6至8格区域，至少4个位置变体，12至18秒后消散 |

所有关卡必须满足：

- 不使用道具也可以正常瞄准、发射和通关。
- 初始总遮挡不超过普通泡泡数量的25%。
- 不遮挡顶部锚定行。
- 不遮挡初始最低危险行。
- 不遮挡关卡需要玩家立即识别的特殊泡泡。
- 同一关卡所有遮挡区必须使用与`playMode`一致的同一种倒计时。
- 所有位置变体保持相同遮挡数量、覆盖格数和清理规则。
- 连续两次普通主线关尝试不得选择同一位置变体。

建议增加以下运行时事件：

```text
board_occlusion_cleared
board_occlusion_warning
powerup_snow_removal
```

`board_occlusion_cleared`至少包含：

```text
zone_id
visual_type
clear_reason
remaining_shots
remaining_time_ms
attempt_seed

```

建议统计：

- 玩家是否使用除雪剂清理遮挡。
- 道具使用发生在剩余多少次数或时间。
- 自动消散数量。
- 胜利或失败时仍存在的遮挡区数量。
- 有遮挡关与无同类遮挡关的胜率、平均发射数和道具使用率差异。
- 各位置变体的抽取次数、胜率、平均发射数和道具使用率差异。
- 同一关卡是否出现连续重复变体；该指标必须始终为0。

## 16. Fail-Fast要求

实现必须遵守以下原则：

- 配置字段缺失直接报错。
- 遮挡资源缺失直接报错。
- 遮挡层或必要节点缺失直接报错。
- 非法区域坐标、重叠区域和不连通区域直接报错。
- Start Context中的`seed`缺失或为空、`attemptIndex`非法、`runMode`缺失时直接报错。
- `selectedVariantId`无法从种子和历史状态复算时直接报错。
- 动态模式变体不足、变体ID重复、规则不一致、完全相同或重叠比例超标时直接报错。
- Runtime Snapshot结构不符合合同直接报错。
- 道具成功结果缺少快照或清理事件直接报错。
- 禁止通过默认空数组、默认视觉类型、默认倒计时、默认种子或静默跳过遮挡区来维持运行。
- 禁止选位失败后使用第一个变体、固定位置或继续重抽作为兜底。
- 禁止为旧Schema增加兼容分支。

## 17. 验收标准

### 17.1 配置

- 本地和远程全部关卡通过新Schema校验。
- 压缩、解压后遮挡配置完全一致。
- manifest字节数和SHA-256与新关卡包一致。
- 所有动态关至少拥有合同要求的位置变体数量。
- 每个变体独立通过坐标、连通、特殊实体、覆盖率和重叠校验。
- 同一关卡所有变体的遮挡ID、类型、规则和覆盖格数一致。
- 关卡编辑器可完整导入、编辑、保存和重新加载遮挡计划及全部位置变体。
- 相同种子、历史变体和生成器版本始终解析出相同结果。

### 17.2 玩法

- 遮挡状态不改变`BubbleGrid`格子数量和版本。
- 遮挡不影响轨迹、碰撞、消除、掉落和危险线。
- 普通主线关连续两次开局的`selectedVariantId`不同。
- 暂停、切后台和弹窗恢复不会改变当前遮挡位置。
- 重建渲染节点后仍使用同一份`activeZones`。
- `per_run`随机挑战重试保持相同遮挡位置。
- `per_attempt_no_repeat`重玩产生新种子并避开上一次变体。
- 发射次数在完整结算后只减少一次。
- 道具使用不减少发射次数。
- 暂停和教学期间秒数不减少。
- 自动消散和玩家点击竞争时最多产生一次清理。
- 道具只在成功清理后扣除。
- 遮挡区覆盖泡泡全部清空时，即使倒计时尚未结束也会立即消失并正常进入胜利流程。

### 17.3 表现与性能

- 遮挡区随棋盘视口位移保持正确位置。
- 漩涡、虫洞和藤蔓动画期间层级正确。
- 爆炸、碎裂和掉落反馈显示在遮挡层前方。
- 倒计时数字只在显示值变化时更新。
- 普通关每次完成一次发射结算后，遮挡物正中的剩余发射次数立即减一且始终显示在遮挡视觉之上。
- 遮挡节点在显示桶变化或离开关卡时停止动作并销毁。
- 返回选关后不保留遮挡节点、SpriteFrame或动画引用。

### 17.4 生成玩法代码

如果实施涉及`gameplay-src`，必须重新生成微信玩法资产，并执行对应的玩法、关卡内容、远程关卡同步、关卡编辑器和生成bundle校验。源代码校验通过但生成资产未同步，不能视为完成。
